# Tikitaka + grid + 편별 재관찰

2026-09-14. 원격 `origin/tikitaka`의 `8961e3b8a32db1a306f41bffd6d98439bce6ad1c`를 기반으로 현재 `v3-human-flow`의 grid·재관찰·연출을 연결했다. 커밋 관계는 [브랜치 비교](tikitaka_vs_v3_human_flow.md)를 참조한다.

## 실행

`python -m app.tikitaka`의 기본 경로가 `grid-review`다. 기존 `app.cli`와 `app.v3` 진입점은 유지한다.

```bash
python -m app.tikitaka \
  --source "/path/episode.mp4" \
  --title "작품명" --episode 1 \
  --count 3 --out "outputs_tikitaka_grid/작품명_1"
```

전사는 기본 ElevenLabs Scribe v2이며 `ELEVENLABS_API_KEY`가 필요하다. `--stt whisper`로 선택할 수도 있다. 영상 관찰·대본·연출에는 Gemini 키, 렌더에는 ffmpeg/ffprobe가 필요하다. 두 Gemini 슬롯 기본값은 공통 모델 정책의 `gemini-3.7-flash`이며 기존 환경변수 재정의를 따른다.

2026-09-15: grid-review는 전사 전에 v3와 동일한 `work_researcher.research_work()`로 작품·인물·관계·해당 회차까지의 줄거리를 검색한다. `checkpoint_research.json`은 v3와 같은 형태이며, 별도 meta 파일로 작품명·회차를 검증한다. 전사 키워드와 grid 관찰, 이후 digest·대본·검증에 같은 리서치를 전달한다. 가이드 인물=배우 대응이 검색 결과보다 우선하고, 영상으로 식별이 불확실하면 미상으로 기록하도록 요청한다. 이는 인물 식별의 정확도를 보증하는 별도 얼굴 검증은 아니다.

- `--until research`: 리서치 결과만 저장한다.
- `--redo research`: 리서치와 index 이후를 다시 만든다. 기존 전사·교정은 보존하므로 STT 키워드까지 새로 적용하려면 `--redo research,transcribe`를 사용한다.
- `--skip-research`: 검색만 생략한다. 가이드 인물 정보와 명시 `--cast`는 관찰에 전달한다.
- 리서치·인물 후보 변경은 grid 캐시 지문에 포함하며, 옛 관찰 결과와 섞지 않는다. 재관찰 시 기존 화자 대조 결과도 보존 후 무효화한다.
- 리서치의 grounding 미지원 폴백·검색 실패 후 빈 결과 진행은 v3 공유 함수의 동작을 따른다. 빈 결과는 경고하고 다음 실행에서 다시 검색한다. 외부 검색 결과는 영상 관찰의 대체물이 아니다.

- `--version 1,3`: 특정 버전을 각각 완성한다. `--all-versions`: 14전략 전체.
- `--design-preset <이름 또는 경로>`: v3 디자인과 편집 지침·활용 불가 구간을 연결한다. 노래 자막 제거 옵션은 이 경로에서 지원하지 않아 명시적으로 거절한다.
- `--guide <파일>`: 제작 가이드. 기본은 `guides/tikitaka/<작품명>.md`와 회차별 파일 자동 탐색이며 `1`, `1화`, `1회`를 대응한다.
- `--layout fill|band`: 기본 5:6 크롭 또는 16:9 밴드. `--no-framing`: 화자 추적 해제.
- `--until table`: 대본·덮개 검증과 조립표까지 생성한다.
- `--pipeline legacy`: 가져온 tikitaka의 인덱스·프레이밍·효과·렌더 경로. 별도 출력 디렉토리를 사용한다. 공통 모델 정책과 가이드 경로 수정은 이 경로에도 적용된다.

## 처리 순서

1. **v3 리서치 + Tikitaka 전처리**: 작품·등장인물 리서치 → 전사 → 글자 교정 → 장면 전환·암전 검출.
2. **Grid 인덱스**: 단어 시각·장면 경계·실측 무음·오디오 강도로 시간 구간을 먼저 만든다. AI는 구간 ID에 관찰 내용을 붙이며 새 시각을 만들 수 없다. 사진 대조 검사와 원본 해상도 화면 글자 정독을 연결한다.
3. **Tikitaka 대본**: 화자 대조 → 작품 이해 문서 → 14전략 리빌딩 → 순위 → 선택한 버전 영상 확인. 화면 글자와 회상·상상 정보를 대본 입력에 포함한다.
4. **Grid 조립**: N(내레이션)·S(대사)·A(현장음)를 유지한다. S는 전사 시각, N 덮개는 같은 씬의 미사용 grid ID를 사용한다. 일반 덮개는 실제 TTS 길이를 화면이 채운다. **대사 바로 앞 장면을 덮개로 선택하면 장면 길이가 우선**이며, 긴 내레이션을 다시 써서 재합성한다. 현장음과 대사 중복은 먼저 다듬고 남은 중복은 실패시킨다.
5. **한 편씩 재관찰**: 각 버전의 실제 내레이션이 들어간 초안을 만든 뒤 v3 `watch_trim`으로 다시 본다. 대사·TTS·마지막 컷을 보호하고, 허용한 트림만 30fps 격자에 맞춰 적용한다. 자막과 TTS도 함께 재매핑한다.
6. **한 편씩 연출·완성**: 다듬은 초안에 v3 Stage 4를 실행해 효과 자막·강조·줌·정보 화면 맞춤을 결정한다. v3 최종 렌더로 화자 추적과 효과음을 적용한 뒤 영상 크기·길이·오디오 길이를 검증한다.

재관찰은 무제한 재작성 루프가 아니다. 초안별 재관찰 결과를 저장하며, 명시적으로 다시 요청하거나 조립 재료가 바뀔 때 갱신한다.

## 첨부 규칙 적용

[v3 연출 규칙](v3_effects_speaker_props_rules.md)의 코드 정본을 복제하지 않고 직접 호출한다.

| 규칙 | 연결 및 범위 |
|---|---|
| 라벨·강조·줌·fit | `app/v3/stage4.py`의 이벤트 앵커, 인물 조건, 개수 상한, 라벨 프로브, 강조와 줌 결합을 사용 |
| 화자 추적·고정 크롭 | `app/v3/finalize.py`의 YuNet 발화 구간 고정과 사람 지정 크롭 우선순위를 사용 |
| 소품·화면 글자 | grid 관찰에 원문·종류·등장인물·피사체 위치·diegesis를 저장하고 공통 원본 정독 패스에 전달 |
| 내레이션 덮개 | 같은 씬, 미사용 ID, 첫 N 훅의 첫 화면 중요도 4 이상. 일반 배치는 최대 4컷·컷당 최대 2초, 자료화면만 최대 2초 hold. 대사 앞 고정 장면 배치는 hold 없이 내레이션을 장면 길이에 맞춰 재작성 |
| 덮개 전수 검사 | 선택한 각 화면을 실제 클립으로 확인. 모순이면 최대 2번 재선택하고 해결되지 않으면 해당 편을 실패·기록 |
| 소리 | 공통 라벨 pop·강조 hit 및 반복 회피 규칙을 최종 렌더에서 사용 |
| 시간 불변 | 트림 뒤 연출은 조립 총 길이를 바꾸지 않음. 최종 영상 길이를 프레임 단위 허용 오차로 확인 |

회차 레지스터를 새로 만드는 단계는 연결하지 않았다. 따라서 근거 ID가 필요한 `irony` 라벨은 허용하지 않는다. 선택 내레이션을 자동 삭제하는 v3 walk 전체를 이식한 것은 아니며, 이 경로에서는 덮개 검증 실패를 편별 오류로 남긴다. 사람 덮개 편집을 구분하는 전용 UI/오버라이드 경로도 추가하지 않았다.

`--tag`가 있으면 버전 산출에 접미사를 붙인다. 같은 `--out`에 다른 원본·파이프라인·전사 백엔드를 섞으면 거절한다.

아래 옵션은 최초 실행과 같은 원본·작품·출력 경로 옵션에 추가한다.

```bash
--version 1 --redo review  # 그 편 초안을 다시 보고 트림·연출·렌더
--version 1 --redo style   # 트림 결과는 유지하고 연출부터 다시
--version 1 --redo render  # 재관찰·연출 결과를 재사용해 렌더만 다시
--version 1 --redo table   # 덮개 선택·검증부터 다시 조립
```

제목·크롭 같은 외형 변경만으로 트림을 다시 묻지 않는다. 연출은 관련 입력·소스가 바뀌면 갱신될 수 있다. 효과음 코드·자산과 렌더 코드 변경은 렌더 지문에 포함하므로 해당 변경을 캐시가 숨기지 않는다. 교체되는 최종본은 편 디렉토리에 `final_prev_*.mp4`로 보존한다.

## 검증 범위

기존 Tikitaka·v3·전사·효과음·프레임 정렬 회귀 테스트와 새 연결 테스트 **954개가 통과**했다. 합성 영상에서 실제 ffmpeg 렌더, 1080×1920 크기, 영상/오디오 길이, 내레이션 주파수, 라벨·강조·줌·fit·효과음 적용을 확인했다. 모델 판단은 테스트 응답으로 대체했다.

실제 회차 영상으로 Gemini·ElevenLabs를 호출하는 전체 생성과 얼굴 추적 품질·스토리 품질의 실사 검수는 아직 수행하지 않았다. 이 구현 검증만으로 실사 편집 품질까지 승인된 것은 아니다.

## 대사 앞 장면에 맞추는 내레이션 (2026-09-14 후속 변경)

`app/tikitaka/grid_table.py`의 `before_dialogue` 배치에 적용한다. 조립 순서가 N → S이고, S 바로 앞의 원본 장면이 내레이션과 맞을 때 우선 선택하도록 요청한다. 단순히 N이 대사 앞에 있다는 이유만으로 무관한 화면을 강제로 채택하지 않는다.

1. 다음 S 컷의 시작점 직전, 같은 씬의 마지막 샷에서 사용하지 않은 연속 구간을 구한다. 장면 전환·금지 구간·이미 사용한 컷을 넘지 않는다. Grid ID가 실제 구간을 제공하고, 대사 시작점은 전사 기반 S 컷에서 가져온다.
2. 이 앞 장면을 선택하면 길이를 고정한다. **TTS가 길면 원문 의미와 다음 대사로의 연결을 유지하도록 다시 쓴다.** 같은 목소리·속도로 합성하고 실제 길이를 재측정한다. 글자 수는 참고치이며 통과 판정은 음성 길이다.
3. 최대 3회 재작성한다. 짧아져도 핵심 인물·행동이 바뀌거나 새 사실·시간 단정이 생긴 문장은 의미 검수로 반려한다. 제작 가이드도 재작성·검수에 전달한다.
4. 길이와 의미를 통과한 **새 문장으로 화면 프로브를 다시 실행**한다. 최종 문장·음성·길이를 조립표와 그 안의 대본에 반영하고, 이후 초안·자막·연출은 이 결과를 사용한다. 상류 `rebuild`·`verified` 후보 원문은 보존한다.
5. 음성이 짧으면 대사 직전에서 끝나도록 앞 장면의 뒤쪽을 사용한다. 이미 짧은 원문은 재작성하지 않는다. 이 배치는 자료화면이라도 hold가 없으며, 속도를 올리거나 다른 장면으로 늘려 실패를 숨기지 않는다. 재작성 소진은 편별 실패다.

기록: `cover_review[].narration_fit`와 `narration_fit/`에 원문·시도별 문장·실측 길이·의미 판정을 남긴다. 실패 시 `review_vN.json`에 `blocked`와 사유를 저장한다. `grid_table` 스키마 지문을 올려 이전 조립 캐시를 재사용하지 않는다. 일반 `same_scene` 덮개의 컷 쌓기·자료화면 hold 규칙은 유지한다. 문장 길이 재작성 테스트는 모델·TTS 응답을 대체한 테스트이며 실사 API 품질 검증은 별도다.

## v3 분석 재사용 (2026-09-15, 현재 실행 경로)

기본 grid-review는 `v3_analysis.build_index`를 사용한다. 종전 `grid.build_index`의 10분 창 관찰 프롬프트는 더 이상 기본 실행에서 호출하지 않는다.

기존 Tikitaka 전사·교정 → v3 grid → **공유 Stage 1 전체 분석·exception 보정 → 의미 청크 재단(480p/10fps) → 공유 Stage 2 분석·검증·화면 글자 정독** → Tikitaka index 변환 → 기존 digest·14전략·편별 확인·조립·재관찰·연출 순서다. 모델 영상 샘플링과 최종 사진 반려 정책도 공유 v3 함수를 따른다. 전사 backend는 기존 선택을 유지한다.

Stage 2는 v3 `_run_m2`를 재사용해 청크별 증분 체크포인트와 실패 격리를 유지한다. `--retry-failed-chunks`는 성공 청크를 유지하고 실패 청크만 재시도한다. `--redo index`는 분석 전체를 다시 만든다. 분석 캐시는 원본·grid·리서치·모델·공유 분석 코드 지문별 하위 디렉토리에 분리한다.

v3가 없는 reaction/action 종류나 소리 이름을 새로 추측하지 않는다. 무성 순간의 kind는 중립적인 ambience로 전달하고 원본 scene_script는 유지한다. v3 청취 문구가 Tikitaka 자막 문구를 덮어쓰지 않는다. Stage 1 제외·실패 청크는 대본과 덮개·렌더에서도 배제한다.

필드별 실제 소비 및 보존만 하는 항목: [스키마 사용 표](tikitaka_v3_schema_usage.md). 기존 성공 EP01 기록을 변환해 데이터 보존과 대본 입력을 검증했다. 새 경로의 유료 전체 생성·최종 렌더 실측은 아직 수행하지 않았다.

### 2026-09-15 덮개 검증·길이 재시도 보정

- 시각 대조는 실제 인물·행동·소품의 모순과 무관한 장면을 거절한다. 관점 전환 안내나 기록 속 발언이 화면 글자로 보이지 않는다는 이유만으로 거절하지 않도록 프롬프트를 구분했다. 인물 식별 불확실성은 검증 사유에 남긴다.
- 선택 프롬프트에 프레임 정렬 및 컷당 2초 상한을 반영한 `usable_sec`를 전달한다. 반려된 동일 선택은 재검사하지 않으며 재선택 요청에 누적해서 전달한다.
- 일반 same_scene 배치도 유효한 선택 화면이 TTS보다 짧으면 기존 내레이션 축약·재합성·의미 보존 검사를 사용한다. 예산은 원본 구간 길이 합이 아니라 실제 조립 가능한 길이다. 축약 후 같은 화면으로 다시 조립하고 시각 대조를 수행한다. 실패하면 명시적으로 중단한다.
- 테이블 및 프로브 캐시 버전을 바꿔 이전 판정이 새 규칙을 우회하지 않게 했다. 분석·리서치·대본 캐시는 재사용한다.

- 대사 앞 배치의 축약 예산도 실제 뒤에서부터 조립할 수 있는 최대 4컷으로 계산한다. 긴 span을 2초씩 나누는 데 쓰이는 컷 수까지 포함해, 축약 통과 후 조립에서 컷 수 초과로 실패하던 불일치를 제거했다.
- 최종 렌더는 Tikitaka의 30fps 편집 시간축을 `output_fps=30`으로 명시한다. 원본이 23.976fps여도 프레임 수 고정 전에 CFR 변환하므로 영상이 늘어나지 않는다. 이 명시 경로는 유효한 1프레임 이상 조각을 보존하고, 컷 유실 시 실패한다. 옵션 미지정인 기존 생성/v3 렌더는 기존 fps 및 0.2초 하한을 유지한다.
- 회귀 확인: 23.976fps/30fps 합성 소스에 짧은 2프레임 조각을 포함한 실렌더, 영상·오디오 길이 및 내레이션 주파수 확인, 관련 테스트 198개 통과.

### V3 제목·배치 연결 (2026-09-15)

- grid-review에서 `--layout` 미지정이면 V3 `drama_clip`의 영상 비율·위치를 읽고 채널 프리셋을 덮는다. 명시 fill/band 옵션과 legacy 기본 fill은 유지한다.
- 기존 Tikitaka 제목 문구는 단어를 보존해 두 줄로 나누고 V3 `title.line1/line2` 및 `layout.top_title` 줄바꿈으로 전달한다. 명시된 두 줄은 보존한다. 줄별 색·크기·폭 맞춤·영상 상대 위치·안전 영역은 V3 finalize의 공통 계산을 사용한다.
- 채널의 `platform_text`와 제작 가이드 카피가 같으면 가이드의 아래쪽 카피를 중복해서 추가하지 않는다. 채널 프리셋이 정한 플랫폼 위치를 사용한다.

### 리서치 전사 교정과 짧은 대사 자막 (2026-09-15)

- 전사 교정에 인물 이름 목록뿐 아니라 연구·가이드의 인물/배우 대응 문맥을 전달한다. 오디오와 앞뒤 대사가 뒷받침할 때 극중 정식 이름으로 교정하며, 배우명으로 대체하거나 사전에 없다는 이유로 강제 치환하지 않는다.
- `polished=True`만으로 건너뛰지 않는다. 원문·시각·소스·작품·인물 목록·리서치·프롬프트 지문을 비교한다. 지문이 바뀌면 원문에서 다시 교정하고, 같은 조건의 성공한 창은 재사용한다. 실패한 창이 있으면 완료로 표시하지 않는다.
- `--until polish`로 전사 교정까지만 실행 가능하다. 교정으로 텍스트가 바뀌면 `transcript_dependents_dirty.json`을 남겨 다음 전체 실행에서 이전 대본/편집/렌더 캐시를 백업 후 무효화한다.
- 렌더 연결부는 최신 교정 텍스트를 원래 단어 시각에 맞추고 V3 `assemble._lines_for_span`을 사용한다. 기본 12자·4어절, 의존명사/조사와 짧은 부사의 경계 벌점, 최소 0.35초 및 짧은 꼬리 병합 규칙을 그대로 따른다. 이 변경은 대사 자막에 적용하며 TTS 문구·음성은 유지한다.
- 교정으로 단어 개수가 달라져 개별 대응이 불확실하면 해당 묶음을 원래 단어 구간 안에서 함께 표시한다. 임의로 단어 시각을 균등 배분하지 않는다. 렌더에 쓰인 구절·교정 지문은 `subtitle_table_vN.json`에 보존한다.

### 행동·장면 중심 덮개와 도입 검수 (2026-09-15)

- `cover_evidence.retrieve`가 편 전체의 장면 요약에서 내레이션별 직접 행동/장면을 먼저 검색한다(최대 3개 씬). 다음 대사와 같은 씬이라는 제한을 풀어 과거 행동을 자료화면으로 사용할 수 있다. 활용 불가 시각·중복 사용·가이드 금지어 후보는 제외한다.
- 선택 순서는 직접 행동/장면 > 관련 상황 > 대사 직전 연결 화면이다. 인물이 같다는 것만으로 다른 행동을 대체하지 않는다. 최종 선택은 기존 실제 클립 대조를 통과해야 한다.
- 첫 행이 길고 대사가 없는 단일 현장음 컷이면 별도 영상 검수를 한다. 정적이고 의미 있는 현장음이 없다는 판정이 함께 나온 경우에만 1초로 줄인다. 유성 span·행동 진행·핵심 소리는 유지한다. 판정과 적용 전후 길이를 `opening_review`에 남긴다.
- grid-review의 `watch_trim`은 첫 3초의 행동/사건 변화와 정적인 대기 시간을 별도로 평가하도록 요청한다. 기존 대사·TTS 보호 규칙은 유지한다. 이 추가 요청은 다른 v3 경로에는 기본 적용하지 않는다.

### 내레이션 구절 자막 (2026-09-15)

- 이미 합성된 내레이션 음성을 Scribe로 단어 시각만 측정하고, 합성에 쓴 정본 문구를 그 시각에 정렬해 V3 구절 분할을 적용한다. 음성 파일과 TTS cue는 그대로이며 자막 트랙만 여러 창으로 나뉜다.
- 음성 내용 해시·문구로 `tts_word_alignment`를 캐시한다. 컷 편집으로 cue 위치가 이동해도 다시 전사하지 않고 표시 시각만 이동한다. 구절 목록은 `tts_caption_segments.json`에 저장한다. 기존 V3 경로는 이 추가 목록이 있을 때만 사용한다.
- 짧은 덮개/도입 검수 클립과 grid-review의 작은 watch_trim 초안은 인라인 영상으로 전달해 Files API의 반복 500 오류를 피한다. watch_trim 호출 실패 체크포인트는 다음 실행에서 검수를 재시도하며, 동일한 초안 영상은 재렌더하지 않는다.
