# Tikitaka + grid + 편별 재관찰

2026-09-14. 원격 `origin/tikitaka`의 `8961e3b8a32db1a306f41bffd6d98439bce6ad1c`를 기반으로 현재 `v3-human-flow`의 grid·재관찰·연출을 연결했다. 커밋 관계는 [브랜치 비교](tikitaka_vs_v3_human_flow.md)를 참조한다.

## 실행

`python -m app.tikitaka`의 기본 경로가 `grid-review`다. 기존 `app.cli`와 `app.v3` 진입점은 유지한다.

```bash
python -m app.tikitaka \
  --source "/path/episode.mp4" \
  --title "작품명" --episode 1 \
  --count 3 --out "outputs_tikitaka_grid/작품명_1"
```

전사는 기본 ElevenLabs Scribe v2이며 `ELEVENLABS_API_KEY`가 필요하다. `--stt whisper`로 선택할 수도 있다. 영상 관찰·대본·연출에는 Gemini 키, 렌더에는 ffmpeg/ffprobe가 필요하다. 두 Gemini 슬롯 기본값은 공통 모델 정책의 `gemini-3.7-flash`이며 기존 환경변수 재정의를 따른다.

- `--version 1,3`: 특정 버전을 각각 완성한다. `--all-versions`: 14전략 전체.
- `--design-preset <이름 또는 경로>`: v3 디자인과 편집 지침·활용 불가 구간을 연결한다. 노래 자막 제거 옵션은 이 경로에서 지원하지 않아 명시적으로 거절한다.
- `--guide <파일>`: 제작 가이드. 기본은 `guides/tikitaka/<작품명>.md`와 회차별 파일 자동 탐색이며 `1`, `1화`, `1회`를 대응한다.
- `--layout fill|band`: 기본 5:6 크롭 또는 16:9 밴드. `--no-framing`: 화자 추적 해제.
- `--until table`: 대본·덮개 검증과 조립표까지 생성한다.
- `--pipeline legacy`: 가져온 tikitaka의 인덱스·프레이밍·효과·렌더 경로. 별도 출력 디렉토리를 사용한다. 공통 모델 정책과 가이드 경로 수정은 이 경로에도 적용된다.

## 처리 순서

1. **Tikitaka 전처리**: 전사 → 글자 교정 → 장면 전환·암전 검출.
2. **Grid 인덱스**: 단어 시각·장면 경계·실측 무음·오디오 강도로 시간 구간을 먼저 만든다. AI는 구간 ID에 관찰 내용을 붙이며 새 시각을 만들 수 없다. 사진 대조 검사와 원본 해상도 화면 글자 정독을 연결한다.
3. **Tikitaka 대본**: 화자 대조 → 작품 이해 문서 → 14전략 리빌딩 → 순위 → 선택한 버전 영상 확인. 화면 글자와 회상·상상 정보를 대본 입력에 포함한다.
4. **Grid 조립**: N(내레이션)·S(대사)·A(현장음)를 유지한다. S는 전사 시각, N 덮개는 같은 씬의 미사용 grid ID를 사용한다. 실제 합성한 TTS 길이를 화면이 채운다. 현장음과 대사 중복은 먼저 다듬고 남은 중복은 실패시킨다.
5. **한 편씩 재관찰**: 각 버전의 실제 내레이션이 들어간 초안을 만든 뒤 v3 `watch_trim`으로 다시 본다. 대사·TTS·마지막 컷을 보호하고, 허용한 트림만 30fps 격자에 맞춰 적용한다. 자막과 TTS도 함께 재매핑한다.
6. **한 편씩 연출·완성**: 다듬은 초안에 v3 Stage 4를 실행해 효과 자막·강조·줌·정보 화면 맞춤을 결정한다. v3 최종 렌더로 화자 추적과 효과음을 적용한 뒤 영상 크기·길이·오디오 길이를 검증한다.

재관찰은 무제한 재작성 루프가 아니다. 초안별 재관찰 결과를 저장하며, 명시적으로 다시 요청하거나 조립 재료가 바뀔 때 갱신한다.

## 첨부 규칙 적용

[v3 연출 규칙](v3_effects_speaker_props_rules.md)의 코드 정본을 복제하지 않고 직접 호출한다.

| 규칙 | 연결 및 범위 |
|---|---|
| 라벨·강조·줌·fit | `app/v3/stage4.py`의 이벤트 앵커, 인물 조건, 개수 상한, 라벨 프로브, 강조와 줌 결합을 사용 |
| 화자 추적·고정 크롭 | `app/v3/finalize.py`의 YuNet 발화 구간 고정과 사람 지정 크롭 우선순위를 사용 |
| 소품·화면 글자 | grid 관찰에 원문·종류·등장인물·피사체 위치·diegesis를 저장하고 공통 원본 정독 패스에 전달 |
| 내레이션 덮개 | 같은 씬, 미사용 ID, 첫 N 훅의 첫 화면 중요도 4 이상. 최대 4컷·컷당 최대 2초. 자료화면만 최대 2초 hold, 슬로우 없음 |
| 덮개 전수 검사 | 선택한 각 화면을 실제 클립으로 확인. 모순이면 최대 2번 재선택하고 해결되지 않으면 해당 편을 실패·기록 |
| 소리 | 공통 라벨 pop·강조 hit 및 반복 회피 규칙을 최종 렌더에서 사용 |
| 시간 불변 | 트림 뒤 연출은 조립 총 길이를 바꾸지 않음. 최종 영상 길이를 프레임 단위 허용 오차로 확인 |

회차 레지스터를 새로 만드는 단계는 연결하지 않았다. 따라서 근거 ID가 필요한 `irony` 라벨은 허용하지 않는다. 선택 내레이션을 자동 삭제하는 v3 walk 전체를 이식한 것은 아니며, 이 경로에서는 덮개 검증 실패를 편별 오류로 남긴다. 사람 덮개 편집을 구분하는 전용 UI/오버라이드 경로도 추가하지 않았다.

## 산출물과 다시 다듬기

| 파일 | 용도 |
|---|---|
| `grid.json`, `grid_index.json`, `stage2.json` | 시간 정본과 관찰 근거 |
| `rebuild.json`, `verified_vN.json` | Tikitaka 후보 대본과 영상 확인 결과 |
| `grid_table_vN.json`, `master_table_vN.md` | N/S/A 조립표, 덮개 ID·검증 내역 |
| `review_vN/draft_480.mp4` | 해당 편 재관찰용 초안 |
| `review_vN/checkpoint_review.json` | 트림 후 조립·자막·TTS 상태 |
| `review_vN/checkpoint_style.json` | 해당 편의 연출과 감사 기록 |
| `review_vN/review.json`, `review_vN.json` | 검토 항목·회상/상상 표시·검증 결과 |
| `shorts_vN.mp4`, `publish_vN.json` | 최종 영상과 게시용 메타데이터. 외부 게시를 수행하지 않음 |

`--tag`가 있으면 버전 산출에 접미사를 붙인다. 같은 `--out`에 다른 원본·파이프라인·전사 백엔드를 섞으면 거절한다.

아래 옵션은 최초 실행과 같은 원본·작품·출력 경로 옵션에 추가한다.

```bash
--version 1 --redo review  # 그 편 초안을 다시 보고 트림·연출·렌더
--version 1 --redo style   # 트림 결과는 유지하고 연출부터 다시
--version 1 --redo render  # 재관찰·연출 결과를 재사용해 렌더만 다시
--version 1 --redo table   # 덮개 선택·검증부터 다시 조립
```

제목·크롭 같은 외형 변경만으로 트림을 다시 묻지 않는다. 연출은 관련 입력·소스가 바뀌면 갱신될 수 있다. 효과음 코드·자산과 렌더 코드 변경은 렌더 지문에 포함하므로 해당 변경을 캐시가 숨기지 않는다. 교체되는 최종본은 편 디렉토리에 `final_prev_*.mp4`로 보존한다.

## 검증 범위

기존 Tikitaka·v3·전사·효과음·프레임 정렬 회귀 테스트와 새 연결 테스트 **950개가 통과**했다. 합성 영상에서 실제 ffmpeg 렌더, 1080×1920 크기, 영상/오디오 길이, 내레이션 주파수, 라벨·강조·줌·fit·효과음 적용을 확인했다. 모델 판단은 테스트 응답으로 대체했다.

실제 회차 영상으로 Gemini·ElevenLabs를 호출하는 전체 생성과 얼굴 추적 품질·스토리 품질의 실사 검수는 아직 수행하지 않았다. 이 구현 검증만으로 실사 편집 품질까지 승인된 것은 아니다.
