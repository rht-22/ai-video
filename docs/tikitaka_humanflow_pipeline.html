01

원본 준비 — 영상과 소리를 먼저 잽니다

probe · proxy · scene cuts · transcribe · polish

원본의 길이와 해상도를 읽고, 장면 분석용 작은 영상과 오디오를 만듭니다. 장면 전환과 암전을 검출한 뒤 대사를 받아쓰고 글자를 교정합니다. 문장이 바뀌어도 단어의 시각은 전사 결과를 기준으로 유지합니다.

02

Grid — 시간은 먼저 정하고, 내용은 나중에 읽습니다

grid.py → v3.timegrid · 영상 관찰 · 사진 대조 · 화면 글자 정독

전사 단어를 먼저 묶어 대사 구간을 만듭니다. 대사 구간을 제외한 0.5초 이상의 틈에서만 무성 조각을 만들고, 장면 경계로 나눕니다. 6초를 넘는 조각은 무음 검출 경계, 이어 등분으로 더 나눕니다. 오디오 강도도 함께 기록합니다. 각 구간에는 sp0000 같은 ID가 붙습니다. AI는 이 ID에 누가 보이는지, 무슨 행동인지, 어떤 글자가 있는지를 기록하고, 새 시작·끝 시각을 만들어내지 않습니다.

관찰

시간 창별로 영상 읽기

약 10분 단위 창을 보며 구간 ID와 대사 ID에 관찰을 연결합니다. 표에 없는 ID와 중복 답은 걸러 기록합니다.

대조

묘사가 그 화면인지

공통 사진 대조 검사로 표본을 확인합니다. 불일치가 반려 기준에 닿으면 해당 창의 관찰을 다시 요청합니다.

정독

못 읽은 글자는 크게

글자가 있는데 제대로 읽지 못한 구간을 원본 해상도 프레임으로 재확인합니다. 읽은 원문과 화면 종류를 대본·덮개에 전달합니다.

무음 검출 ≠ 무성 조각. 무음 검출은 소리 크기 기준의 보조 신호라 작은 목소리나 전사 시각 오차 때문에 전사와 겹칠 수 있습니다. 최종 무성 조각은 대사 구간의 바깥에서만 만들어 대사와 겹치지 않습니다. 무성 조각에도 음악·효과음·전사가 놓친 말은 있을 수 있으므로 ‘완전한 침묵’이라는 뜻은 아닙니다. 위 그림은 두 입력이 일치하는 단순 예시입니다. 대사 안의 짧은 단어 사이 틈은 별도 조각으로 만들지 않습니다.
Scribe 경로에서는 뒤이어 목소리 군집과 화자 이름을 대조합니다. --no-voice-check로 생략할 수 있습니다. Grid의 숫자가 정확해도 내용 묘사가 틀릴 수 있어, 뒤의 덮개 검사와 초안 재관찰이 계속 필요합니다.

의미 기반 청크로 바꾸려면

연결 제안 · 아직 실행 코드에는 적용하지 않았습니다

현재 분석 창은 600초씩 자르고 마지막 2분 미만의 꼬리를 앞 창에 합칩니다. 의미 기반에서는 전체 영상을 먼저 훑어 사건·대화 흐름별 구간을 잡습니다. 10분은 자르는 간격이 아니라 청크 하나의 최대 길이가 됩니다. Tikitaka 대본 흐름은 그대로 둘 수 있습니다.

유지전사 → Grid단어와 장면 경계 확보
v3 Stage 1 연결전체 흐름 먼저 읽기사건·대화 sequence / 제외 구간
v3 chunk_split 연결의미 경계에서 분할최대 600초 / 원본에서 480p·10fps
그 뒤는 유지Grid 관찰 → 대본작품 이해 · 14전략 · 편별 조립·재관찰

경계와 시간축

Stage 1 경계를 격자에 맞추고, 빈틈·중복·최대 길이를 검사합니다. 청크 상대 시각과 원본 절대 시각의 변환도 함께 바꿉니다.

제외 구간과 문맥

인트로·예고 제외를 대사·대본·덮개에도 전달합니다. 청크를 가로지르는 씬은 부모 sequence와 문맥을 유지하도록 처리해야 합니다.

캐시와 비용

분석 모드·청크 경계를 캐시 지문에 넣습니다. 전체 훑기와 10fps 관찰의 비용을 기록하고 기존 고정 창과 비교합니다.

재사용 대상: seq_analyze.run_seq_analyze → chunk_split.plan_chunks / split_chunks. 교체 지점: grid.build_index의 make_windows 루프. 긴 sequence의 의미 분할을 끝내 얻지 못하면 기존 v3는 기록을 남기고 격자 등분으로 폴백할 수 있습니다.

04

조립 — 대사 앞 장면이 짧으면 문장을 다시 씁니다

grid_table.py · 실제 TTS 길이 · 같은 씬의 ID · 덮개 전수 프로브

대사는 전사의 시각을 따릅니다. 내레이션을 대사 앞에 두고 원본의 바로 앞 장면을 덮개로 선택했다면, 그 장면 길이가 기준입니다. 음성이 더 길면 핵심 뜻을 유지해 다시 쓰고 같은 목소리·속도로 재합성합니다. 일반 덮개는 기존처럼 음성 길이를 화면으로 채웁니다.

  1. N 문장 확정·음성 합성
    내레이션이 실제로 몇 초인지 측정합니다.
  2. 같은 씬의 후보만 열기
    대사와 이미 쓴 화면, 금지 구간·암전을 제외합니다.
  3. 배치에 따라 길이 맞추기
    대사 앞 고정 장면은 긴 문장을 재작성합니다. 일반 덮개는 최대 4개 화면을 이어 붙입니다.
  4. 새 문장의 의미와 화면 재검사
    재작성은 최대 3회. 실측 길이와 의미 검수를 통과한 새 문장으로 화면을 다시 봅니다. 일반 덮개 모순은 최대 2번 재선택합니다.

선택한 버전마다 원음과 실제 TTS가 함께 들어간 초안을 만듭니다. AI가 초안을 보고 늘어지는 구간과 무관한 인서트를 지목합니다. 보호 구간을 침범하지 않는 트림만 적용하며, 잘린 만큼 자막과 내레이션의 완성본 시각도 함께 옮깁니다.

대사 grid 구간과 TTS, 마지막 컷을 보호합니다. 반 문장이나 합성 음성이 잘리는 제안을 거절합니다.

자를 때 함께 옮기는 것

컷은 30fps 격자에 맞추고 남은 짧은 조각을 처리합니다. 자막과 TTS를 같은 기준으로 재매핑합니다.

다시 볼지 결정하는 것

같은 재료면 저장된 결과를 재사용합니다. 외형만 바꿔도 매번 새 트림을 물어 승인한 길이가 흔들리지 않도록 분리했습니다.

무제한 자동 개선 루프는 아닙니다. 한 편의 초안 재관찰 결과를 저장하고, 재료가 달라지거나 --redo review를 요청하면 다시 봅니다. 재관찰 호출 오류가 있으면 검토 기록에 남을 수 있으므로 최종 영상만 보지 말고 review_vN.json도 확인합니다.

초록 = 재실행. 원본·작품명·회차·출력 경로는 최초 실행과 같은 값을 함께 전달합니다. 관련 입력이 바뀌면 캐시 무효화로 상류 단계가 추가 실행될 수 있습니다.

처음 실행하는 명령

python -m app.tikitaka \
  --source "/path/episode.mp4" \
  --title "작품명" --episode 1 \
  --count 3 \
  --out "outputs_tikitaka_grid/작품명_1"
제목·크롭만 바꾸면 트림도 달라지나요?

외형만 바뀐 경우 트림 캐시를 유지합니다. 다만 연출은 관련 입력이나 코드가 달라지면 재생성될 수 있습니다. --redo render는 입력이 같을 때 기존 재관찰·연출을 재사용합니다.

이전 완성본은 어떻게 되나요?

교체할 최종본을 해당 편 폴더의 final_prev_*.mp4로 보존합니다. 재료가 바뀌어 대본을 새로 만들 때도 기존 관련 캐시를 별도 이름으로 보관합니다.

원래 Tikitaka 경로도 있나요?

--pipeline legacy로 원래 인덱스·프레이밍·효과·렌더 경로를 선택합니다. 새 grid-review와 출력 폴더를 분리해야 합니다.

효과음 코드를 고쳐도 옛 영상이 나오나요?

새 경로는 효과음 자산과 렌더 관련 코드 해시를 렌더 지문에 포함합니다. 해당 코드·자산 변경을 감지하면 기존 완성본을 재렌더합니다.
