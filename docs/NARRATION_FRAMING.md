# 내레이션 문맥을 따르는 덮개 구도

`grid-review`는 컷 길이가 확정된 뒤 원본 표본 5장과 해당 문장·앞뒤 문맥으로 보여줄 대상을 고른다. 입 움직임으로 화자를 추정하는 대사 추적과 별개다.

- 인물 설명은 해당 인물의 머리/얼굴, 행동은 손·물건, 자료 화면은 읽어야 할 핵심 숫자·문구에 집중한다.
- v2에서는 전체 원본을 가로로 축소하는 fit을 자동 대안으로 쓰지 않는다. 선택한 대상을 안전 영역에 담을 수 없으면 `needs_review`다.
- 구도는 클립마다 고정한다. 시간·원음·TTS·자막을 바꾸지 않는다. 사람이 지정한 `reframe`이 우선한다.
- 자동 줌과 정보 화면 fit보다 저장된 대상 크롭이 우선한다. `--visual-edit` 사용 시 정보 화면도 관찰 대상으로 포함하며 자동 fit을 막는다.
- `--no-framing` 또는 `face_tracking=false`로 관찰을 끌 수 있다. 시각 편집 strict 모드에서는 관찰하지 않은 자동 구도를 검토 대상으로 남긴다.

`app/tikitaka/cover_framing.py`는 영상 분석용 Pro 슬롯(`GEMINI_MODEL_NAME`, 기본 `gemini-3.7-flash`)으로 관찰하고 `edit_plan.timeline[].narration_framing`에 저장한다. 판정 캐시는 소스 신원·구간·문맥·프롬프트·표본 위치를 포함한다. 좌표가 잘못되면 같은 원본으로 한 번만 재질문하고, 여전히 잘못되면 검토 대상으로 남긴다. API 실패는 성공 캐시로 저장하지 않는다.

`app/v3/narration_framing.py`는 저장된 관찰을 실제 밴드 기하로 검증한다. 대상 박스 전체가 캔버스 가로 안전 영역 x100~980 안에 들어가는 크롭만 적용한다. 불가능하면 검토 미리보기에서 기존 채움 크롭을 유지한다. 재렌더에는 모델 호출이 없다.

산출: `cover_framing.json`(대상·근거·실패), `cover_framing/<hash>.json`(원 응답), `framing_issues.json`(불가능한 크롭), `v3_crop_narration_*.json`(실제 좌표), 렌더 로그 `narration_framing`.

표본 사이 움직임, 인물·좌표 오판 가능성은 남는다. 박스 기하 검사는 실제 모든 프레임의 얼굴 검증이 아니다. 음성과 얼굴의 신원 매칭은 이번 범위에 포함하지 않는다. 검토 및 출력 차단은 [VISUAL_EDIT.md](VISUAL_EDIT.md)를 따른다.
