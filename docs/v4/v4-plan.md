# v4 파이프라인 기획서

**한 줄 정의.** 원본 회차 하나를 통째로 한 번 이해해 쇼츠 후보를 여럿 뽑고, 화면을 안 봐도 아는 결함은 코드로 거르고,
남은 후보만 화면을 다시 보고 결함 게이트를 통과한 편을 **전부** 완성하는 파이프라인.

상세 근거·흡수 지도·캐시 표·결정 이력은 `v4-unified-plan.md`(rev.9), 실측은 `v4-pipeline-plan.md`(rev.7 §2)와 `probes/`.

---

## 1. 원칙 다섯

1. **모델은 관찰하고 제안한다. 판단은 코드가 한다.** 후보 순위·승인·탈락은 전부 순수 함수다. 모델에게 점수를 매기게 하지 않는다.
2. **시간은 전사로 검증한다.** 모델이 낸 구간은 그 구간의 대사가 전사에 실제로 있는지 확인한 뒤에만 쓴다.
3. **절대 임계는 결정적 사실에만.** 소스 밖·예고편 포함·발화 없음 같은 사실만 탈락 사유다. "7점 미만" 같은 점수 임계는 없다.
4. **사람이 이긴다.** 편집실이 고친 값은 어떤 자동 판정도 덮지 않는다.
5. **파일 모양은 바꾸지 않는다.** 현지화·편집실·집계가 읽는 파일은 이름도 모양도 그대로다. 새 정보는 새 파일이나 새 키로만.

## 2. 전체 흐름

```
1 init → 2 research → 3 자막 전사 → 4 probe(눈금·fps) → 5 업로드(720p/30fps)
→ 6 후보 편성 [LLM 1콜 · 후보 5~16]
→ 6b 예고·인트로 경계 정밀 [LLM ≤8] → 6c 구간 검증(전사 대조) [코드]
→ 7 깔때기 [코드 · ≤8] → 8 시각 사고 플래그 [LLM ≤8 병렬] → 9 승인·순위 [코드 · 통과분 전부]
→ 10 살붙이기 [LLM · 승인 편마다] (→ 10a 정밀 청취 · 선택)
→ 11 재료 → 초벌 720p → 스타일 [LLM · HIGH] → 최종 1080p → 검증   (승인 편마다)
```

## 3. 단계별 설명

### 1~5 준비 — 로컬, 요금 0

- **1 init.** 폴더를 열고 `run_log.json` 을 시작한다. 이후 모든 호출의 토큰·소요 시간·모델 버전이 여기 쌓인다.
- **2 research.** 작품 정보와 등장인물을 검색한다. 인물이 3명 미만이면 한 번 더 찾는다. 인명 사전은 전사(3)·검증(6c)·살붙이기(10)·자막 정정(11)이 같이 쓴다.
- **3 자막 전사.** 오디오를 단어 단위 시각으로 받아쓴다. 이 단어 시각이 이후 모든 시간의 **눈금**이고, 6c 검증의 **정본**이다. 단어가 6초 이상 비는 구간은 조건을 바꿔 다시 듣는다. 방송사 자막 파일이 있으면 전사 대신 그것을 쓰고 화면에 명시한다.
- **4 probe.** 길이·해상도·오디오 유무를 재고, 장면 전환과 무음 구간을 뽑아 `grid.json` 눈금을 만든다. 격자는 별도 단계가 아니라 여기서 나오는 **재료**다. 소재 길이와 전사 분량으로 **표본 fps 를 결정**하고, 예산에 못 들어가는 길이는 인코딩·업로드 전에 크게 실패시킨다.
- **5 업로드.** 원본을 720p/30fps 로 줄여 Files API 에 **한 번만** 올린다. 6·6b·8·10a 가 같은 핸들을 쓰고, 삭제는 최종 렌더가 끝난 뒤에만 한다. 재개 시 핸들이 만료됐으면 다시 올리고 기록한다.

### 6~9 고르기 — 후보를 뽑고 걸러 승인한다

- **6 후보 편성 (LLM 1콜, 재질의 ≤2).** 전체 영상을 표본 fps(4/3/2 계단)로 한 번에 보여주고 후보 **5~16개**를 받는다. 후보 하나는 `{id, 템플릿, 조각[{start, end, quote}], 한 줄 사유, 제목 가안 20자}` 로 얇다. 제목·내레이션 본문은 아직 안 쓴다 — 후보마다 다 쓰면 출력이 잘린다. 스토리 템플릿 4종(대사 리캡·하이라이트·갈등형·케미 관찰형)을 축으로 서로 다르게 뽑고, 각 조각에 **대표 대사(quote)** 를 붙이게 한다. 예고·인트로·크레딧 구간도 자가 신고한다. temperature 0, 반려 소진 시 편 실패(시각 정본의 입구라 조용히 통과시키지 않는다).
- **6b 경계 정밀 (LLM ≤3~8).** 신고된 경계마다 ±60초 창을 6fps 로 다시 보고 경계를 정정한다. 창 밖에 경계가 있으면 이어서 한 창 더 본다. 신고가 없는 편은 마지막 180초를 의무 확인한다. 실패하면 원판정 유지 — 잘못 옮기는 것이 안 옮기는 것보다 나쁘다.
- **6c 구간 검증 (코드).** 후보 조각마다 네 가지를 본다. ① 소스 길이 안인가 ② quote 가 **그 구간의 전사**에 있는가(먼저 v1 `find_quote_times` 의 정확 대조, 실패하면 정규화 편집거리 ≤0.35 관용 대조. 판정은 끝점이 아니라 **겹침**이다 — 인용이 여러 cue 에 걸쳐 히트가 조각을 감싸면 끝점 판정은 멀쩡한 조각을 옮긴다) ③ 대사 없는 조각에 quote 가 붙어 있지 않은가 ④ 경계 근처(±2초)에 눈금이 있는가. 판정은 셋 — **ok** / **relocated**(quote 가 다른 시각에만 있으면 그 시각으로 조각 이동) / **dropped**(어디에도 없으면 환각). 조각을 잃어 40초 미만이 되면 후보 드롭, 전량 드롭이면 사유를 붙여 6단계 재질의. 전부 기록한다.
- **7 깔때기 (코드).** 6c 통과분을 ≤8 로 줄인다. 하드 탈락은 예고편 꼬리 구역 포함·소스 밖·발화 커버리지 0.55 미만·길이 위반. 소프트 감점은 정지 화면·문장 중간 절단·결속·루브릭 6항(내레이션 실현 가능성·재료 신뢰도·응집도·진행감·예산·서론 금지). 겹침 IoU 0.5 이상은 하나만 남기고 소스 시각 분포로 다양성을 본다. 같은 입력이면 같은 결과다.
- **8 시각 플래그 (LLM ≤8, 4~8 병렬).** 후보를 렌더하지 않고, 업로드한 파일의 **구간 여러 개를 순서대로 첨부**해 60초짜리 짜집기로 보여준다(첨부 순서 = 편집 순서, 실측 확인). 질문은 둘뿐 — `seam_jump`(이음새에서 인물·장소가 설명 없이 바뀌는가) · `hook_weak`(첫 2초 안에 사건이 없는가). 답은 true/false 와 근거 시각. 호출 실패는 0점이 아니라 **미채점**이다.
- **9 승인·순위 (코드).** **나가도 되는 편 = 결함 게이트 전부 통과**: 7단계 하드 통과 ∧ 6c 통과 ∧ seam_jump=false ∧ hook_weak=false ∧ 채점됨. 통과한 편은 **전부** 승인한다(상한 `--max-shorts` 1~8, 기본 8). 순위(소프트 점수)는 파일 번호와 발행 순서에만 쓴다. 0편이면 1위를 경고와 함께 낸다 — 무인 노드에서 조용한 결번이 가장 나쁘다. 승인·탈락 사유를 전량 기록한다.

### 10 살붙이기 — 승인 편마다

- **10 (LLM 편당 1+1, 병렬).** 제목 두 줄(윗줄 고정·아랫줄 시간대별, 각 20자), 내레이션 문장 배열, 화면 라벨 2~4개(대사 시각에 앵커), 효과 문구를 쓴다. 유튜브 설명·해시태그는 **별도 텍스트 호출**이다. 한 편이 반려를 소진하면 그 편만 탈락하고 다른 편은 그대로다. 편집실에서 "다른 후보로"라고 하면 `--candidate-id` 로 여기부터 재개한다.
- **10a 정밀 청취 (선택, 기본 꺼짐).** 승인 편의 구간(≤180초)만 3fps 로 다시 보고 "들린 대사"를 받는다. 전사가 깨진 자리(반복·퇴화)만 청취 결과로 바꾼다. 효과는 A/B 뒤에 판단한다.

### 11 만들기 — 승인 편마다 다섯 조각

- **11:resources 편집 재료.** 맨 앞에서 자막을 정정한다 — 인명 사전 대조(편집거리 1, 또는 초성 일치 + 거리 2), 반복 줄 제거. 어절 자막, 내레이션 문장을 대사 없는 틈에 배치, TTS 합성(캐시, 편 간 공유). 원음을 끄는 구간은 내레이션이 실제로 점유한 시간만. 사람이 고친 값은 키별로 덮어쓰고 표시를 남긴다. 사람 컷은 눈금에 0.5초 안에서만 스냅한다.
- **11:draft 초벌.** 디자인 없이 컷만 이은 **720p/30fps** 중립 캔버스. 구간만 읽는 seek 방식이라 소재 길이와 무관하게 빠르다.
- **11:style 스타일 (LLM 편당 1, media_resolution HIGH).** 초벌을 6fps 로 보고 연출을 정한다 — 라벨 위치·기울기·색·등장 효과, 컷 리듬에 맞춘 자막 팝, 효과 텍스트·스티커·자막 강조·시간대별 제목. HIGH 는 720p 와 한 세트라 방송 텔롭·잔글씨를 읽어 **피할 자리**를 안다(읽은 글자는 배치 근거로만 쓴다). 범위 밖 값은 버리지 않고 안쪽으로 당긴다. 제목 굵게·회전은 AI 에게 닫혀 있다. 편집실 라운드에서는 이 호출을 다시 하지 않고 기존 연출을 새 타임라인에 옮기기만 한다.
- **11:render 최종.** 1080×1920/30fps. 원본에 박힌 자막 띠를 **전부** 검출해 위로 피하고, 로고를 얹고, 제목 폭을 맞추고, 영상 밖에서 시작하는 내레이션은 버린다. 2위 이하도 연출을 전부 받는다(기존 variant 구멍을 메운다). 산출 `shorts.mp4`·`shorts_2.mp4`….
- **11:validate 검증 (LLM 편당 1).** 차단 셋 — 소스 밖 클립, 예고편 구역 포함, 내레이션이 중요 대사를 덮음. 경고 — 진행감·루프 연속·프레임 4장 검사(잘림·겹침·빈 화면·깨진 글자)·반복·음량·무음·발행 메타 형식. 컷 경계가 눈금 위에 있는 비율을 기록한다(30편 뒤 차단 승격 여부 결정).

## 4. 시간과 예산 규칙

```
상한 판정(400 초과) : count = D × (fps × 71 + 32)     D = 재생초
과금·예산 집계     : usage = D × (fps × 66 + 25)      ← 멀티파트는 이 값으로만 (countTokens 는 3.8배 과소)

예산선 = 1,048,576 − 텍스트 토큰(전사 + 프롬프트·리서치, 실측) − 30,000
fps_cap = floor_0.05( (예산선 − 32·D) / (71·D) )
step    = 4 (≤40분) · 3 (≤60분) · 2 (≤90분) · fps_cap (그 이상)
fps     = min(step, fps_cap)         fps_cap < 0.5 → 4단계에서 크게 실패
# ⚠ 90분 초과 구간은 "fps_cap 대로"가 아니라 min(마지막 계단, fps_cap) 이다 —
#   문구 그대로면 91분이 90분보다 높은 fps 를 받아 소재가 길수록 촘촘해지는 역전이 난다.
```

| 소재 | 요청 fps | 상한 대비 | 비고 |
|---|---|---|---|
| 10~40분 | **4** | 18~72% | |
| 41~60분 | **3** | 84% | 계단 경계 |
| 67분 | **2** | 67% | 비용 표 기준 |
| 90분 | **2** | 90% | 전사 텍스트 ≤79k 일 때만. 넘으면 1.95 로 자동 하향 + 기록 |
| 120분 | 1.35 | 88% | |
| 180분 | 0.65 | 81% | |
| ≈212분 | 0.50 | — | 하한. 그 이상은 실패 |

- 표본 fps 는 `run_log` 에 값과 사유를 남긴다. 파일 30fps 는 표본의 상한일 뿐이고 지금 6 을 넘는 호출은 없다.
- 첫 30편은 fps 2 로 한 번 더 뽑아(shadow) 계단 4/3 이 후보를 실제로 넓히는지 잰다.
- `media_processing=STATIC` 명시, SDK 버전 고정, 첫 실호출에서 산식 재검증.

## 7. 운영 규칙

- **캐시.** 모든 산출은 지문(입력 + 파라미터 + 프롬프트 판)에 묶인다. 파일이 있다고 재사용하지 않는다. 6~9 는 `checkpoint_candidates` 하나에 증분으로 쌓이고, 10·11 은 편별 증분이라 한 편 실패가 다른 편을 되돌리지 않는다.
- **실패.** 편 전체가 실패하는 곳은 둘 — 4단계 길이 초과, 6단계 반려 소진. 6b 는 원판정 유지, 8 은 미채점, 10·11 은 그 편만 탈락, 스타일은 연출 없이 진행. 전부 사유를 남긴다.
- **편집실.** `--edit-overrides` 가 있으면 6~9 를 통째 건너뛴다(사람 편집본은 어떤 후보의 점수도 아니다). 스타일은 재호출하지 않고 재배치만. 사람이 고친 키는 마지막에 얹는다.
- **시간·병렬.** 켜별 타임아웃(6단계 ≥450초)·업로드 상한·편당 벽시계 상한. 8단계와 10단계는 병렬(4→8), 렌더는 직렬. temperature 0, 모델 버전 기록.
- **롤아웃.** 진입점 `python -m app.v4` 는 채널 설정 `pipeline:"v4"` 뒤에만. 전 노드 배포 뒤 채널 키. 롤백은 키 제거 한 동작, 리허설 1회. ves 는 다중 영상 ingest·검수 카드를 먼저 받는다.
