## 1. 🎯 exception 판정 — v3 가 틀린 자리에서 v4 는 맞았다


⇒ **6b 의 꼬리 의무 프로브가 실제로 돌았다.** 모델이 꼬리를 신고하지 않았으므로

## 2. 🛑 6c 가 45초 밀림을 잡았다 — 참 양성

후보 `c05`(오침 온도계 에피소드)의 둘째 조각:

```
모델 주장 : [1180.0, 1240.0]  quote "올라갑니다, 올라갑니다, 올라갑니다, 올라갑니다."
6c 재배치 : [1135.5, 1195.5]  (차이 44.5초)
```

전사로 확인한 결과 **재배치가 옳다**:
- `[1180, 1240]` 실제 내용: "이과였지? … 아, 이게 올라가기는 올라가는데 안 불면 또 바로 떨어집니다 …"
  — `올라갑니다` 연속 발화가 **없다**.
- `올라갑니다` 가 실제로 연달아 나오는 곳은 **1135.5~1139.0**(6회 연속).
- 전사 전체에서 `올라갑` 등장: 1121.2~1123.0(4회) · **1135.5~1139.0(6회)** · 1227.7(1회).
  6c 는 주장 위치에서 **가장 가까운** 히트를 골랐고 그것이 1135.5 다.

⇒ 이것이 6c(운영자 결정 O5)가 존재하는 이유 그 자체다 — 내용은 맞는데 시간축만 밀린 응답
(샤먼 311초 판례와 같은 종류)이 **첫 실소재에서 바로 나왔다.** 이 단계가 없었으면 그 클립은
엉뚱한 장면으로 렌더됐을 것이다.

## 3. ✅ 모델은 인용을 전사에서 그대로 옮긴다

후보 6개 · 조각 11개 전량에서 `find_quote_times` 의 **정확 접두 대조**가 성공했다 —
관용 대조(`fuzzy_match`)로 떨어진 건이 **0건**이다. 6단계 프롬프트의 "그대로 옮겨라" 지시가
실제로 지켜진다. (관용 대조는 그래도 남긴다 — 안전망이 없으면 한 번 어긋날 때 후보가 죽는다.)

판정 요약: `ok 5 · relocated 1 · dropped 0 · clamped 0 · unsnapped 경고 1`.

## 4. 토큰 회계 — 영상 산식은 정확, 텍스트 추정은 36% 과소

```
영상 산식   1993.5초 × (4×66 + 25) = 576,132
실제 prompt_token_count           = 595,033
차(= 텍스트 프롬프트)              =  18,901     ← 24,290자 → 0.778 토큰/자
파이프라인 4단계 추정              =  12,020     ← 36% 과소
```

⇒ **usage 66/25 산식이 실측으로 확정됐다**(차이가 전부 텍스트 몫으로 설명된다).
⇒ `TEXT_TOKENS_PER_CHAR` 를 갈아끼워야 한다. 지금 추정은 전사 글자만 세고 **프롬프트 골격·
격자 요약·템플릿 설명**을 안 센다. 예산이 빠듯한 90분 소재에서 이 36%가 fps 계단을 잘못
고르게 할 수 있다(기획서 §4 의 "텍스트 ≤79k 일 때만 fps 2").
