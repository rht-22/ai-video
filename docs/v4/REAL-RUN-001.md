## 2. 🛑 6c 가 45초 밀림을 잡았다 — 참 양성

⇒ 이것이 6c(운영자 결정 O5)가 존재하는 이유 그 자체다 — 내용은 맞는데 시간축만 밀린 응답

## 3. ✅ 모델은 인용을 전사에서 그대로 옮긴다

### 최종 렌더 — 실패를 **실패로** 확인 (같은 라운드)

사전검사를 탈출구로 우회하고 일부러 끝까지 돌렸다. 목적은 mp4 를 얻는 것이 아니라
**막힐 때 어떻게 막히는지**를 실소재로 보는 것이다.

```
종료 코드 1
RuntimeError: 11:render 최종 — 승인 4편이 전부 실패했다(조용한 결번 금지).
  1위 c04 · 2위 c02 · 3위 c03 · 4위 c08  ← 편마다 사유와 전체 명령을 싣는다
남은 shorts*.mp4  0개                     ← 반쪽 파일이 안 남는다
```

근본 원인은 v4 가 아니다. 이 머신의 Homebrew **ffmpeg 8.1.2 가 축소 빌드**다 —
configuration 에 `--enable-libass`·`--enable-libfreetype` 가 없어 `ass`·`drawtext`
필터 자체가 없다(`Filter not found`). 버전 문제만이 아니라 빌드 옵션 문제다.

이 판에서 **확인된 것 셋**:

1. **`-r 30` 이 실제 argv 에 있다** — `-map [aout]` 뒤 `-c:v` 앞. O9 강제가 합성
   테스트가 아니라 실소재 명령줄에서 확인됐다.
2. **편별 격리가 돈다** — 네 편이 각자 사유를 남기고, 전량 실패라 크게 죽었다.
3. **조용한 결번이 없다** — 반쪽 mp4 도, 빈 산출도 남지 않았다.

되려면 libass 가 있는 ffmpeg 이 필요하다. 기본 ffmpeg 을 안 바꾸는 길:

```
brew install ffmpeg@7      # keg-only — /opt/homebrew 에 심링크되지 않는다
FFMPEG_BIN=/opt/homebrew/opt/ffmpeg@7/bin/ffmpeg python -m app.v4 …
```

⚠ 이 머신은 의존 56개가 빠져 있고 여유가 7.2 GiB 뿐이라 설치는 사람이 판단할
일이다. 운영 노드(mm-01~06)는 ffmpeg 7 이라 그대로 돈다.

## 라운드 3 — 최종 렌더 + 산출물 감사 (2026-09-04)

운영자가 `ffmpeg@7`(keg-only)을 설치해 렌더가 열렸다. `FFMPEG_BIN` 으로 그 바이너리를
가리키면 v1~v4 전 경로가 돈다.
⚠ 그 설치가 x265 를 216 → 217 로 올려 **기존 ffmpeg 8.1.2 가 실행 불가**가 됐다
(`libx265.216.dylib` 링크 끊김). `brew reinstall ffmpeg` 로 복구하되, ai-video 는
지원 범위가 6/7 이라 계속 ffmpeg@7 을 쓴다.

산출물을 오디오·화면·타임라인·검증보고 네 관점으로 독립 조사하고 각 발견을 반증

관측은 맞았지만, 전사 실측상 그 말은 **등장인물의 대사**였다.

정상으로 확인된 것: 영상 밴드 기하가 E10 계약과 픽셀 일치(24장 전부
