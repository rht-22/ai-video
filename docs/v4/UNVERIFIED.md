# 키가 있는 노드가 확인해야 하는 것

M0~M4 를 지을 때 이 워크트리에 `GEMINI_API_KEY` 가 없었다. 코드·계약·배선은 가짜
클라이언트로 전량 고정했지만(테스트 2488건) 모델이 실제로 어떻게 답하는지는 못 봤다.

> ✅ **2026-09-04: 운영자가 `ves.env` 위치를 알려 줘 최우선 4건을 실측으로 닫았다.**
> 재현: `docs/v4/probes/offset_semantics.py`. 아래 §1 의 1·2번과 §2 의 7번이 그 결과다.
> **나머지는 실소재가 있어야 한다**(레이블 7편·실전사·실채널).

이 문서는 그 목록이다. 기획서 §12 의 '확정 아닌 것' 과 짝이고, 여기 있는 것을 확인하기
전에는 **실채널에 투입하지 않는다**(V4-M9 컷오버 전제).

## 0. 무엇이 검증됐고 무엇이 안 됐나

| | 확인됨 | 확인 안 됨 |
|---|---|---|
| SDK 표면 | `VideoMetadata.start_offset/end_offset` 은 문자열(`"120.250s"`) · float 은 ValidationError · 직렬화 열쇠 `startOffset`/`endOffset` · `HttpOptions.timeout` 은 **밀리초** · `fps` 상한 24 · `ThinkingLevel` enum | 서버가 그 값을 어떻게 해석하는가 |
| offset 멀티파트 | 파트 조립·순서 보존·직렬화(SDK) | **서버가 첨부 순서대로 이어 붙여 보는가** — 근거는 REST 프로브뿐, SDK 경로는 선례 0건 |
| 프롬프트 | 필수 지시가 실렸는지·금지 어휘가 안 실렸는지(문자열 검사) | **모델이 그 지시를 지키는가** |
| 검증기·반려 루프 | 항목별 판정·부분 실패·소진 시 fail-loud | 실제 응답이 몇 %나 반려되는가 |
| 토큰 | 산식(count 71/32 · usage 66/25)과 계단 경계 | 멀티파트 실 과금이 산식과 맞는가 |

## 1. 최우선 — 이것이 틀리면 v4 의 전제가 무너진다

1. ✅ **offset 멀티파트를 서버가 첨부 순서대로 이어 붙여 보는가 — 확인됨(2026-09-04).**
   6색 12초 소재로 파트 3개를 역순 배치 두 판, 답도 정확히 역순. **v4 코드 경로**
   (`app/v4/video.call_video`)로 쟀으므로 SDK 배선까지 함께 확인됐다. 기획서 §2-B 의
   REST 실측이 SDK 경로에서도 성립한다.

2. ✅ **좌표계 — 확인됨. 단 파트 수에 따라 갈린다(2026-09-04).**
   · **여러 파트** → 모델은 **이어 붙인 영상의 좌표**로 답한다. 1.4초 파트 3개의 이음새를
     물으면 `[1.4, 2.8]`(정확). ⇒ `app/v4/flags.py` 가 이음새를 편집본 좌표로 주는 것은 맞다.
   · **단일 창** → 모델은 **원본 절대초**로 답한다(원본 4.3~5.7 을 붙이면 `start 4.4`).
     시각을 묻는 단일 창 설계였다면 틀렸을 것이다. `boundary.py` 는 시각이 아니라 **컷
     후보 id** 를 받으므로 이 질문을 비껴간다 — 좌표 프레이밍 A/B 도 3/3 로 동일했다.
   · 덤: 8단계 프롬프트를 실제로 태우니 `seam_jump: true`(설명 없는 전환) ·
     `hook_weak: true`(첫 2초 정지 화면) · `evidence_sec: [1.4, 2.8]` 로 **판정이 맞았다**.

3. **모델이 `quote` 를 전사에서 그대로 옮기는가.**
   6c 가 그 글자로 시각을 검증한다. 다듬어 오면 관용 대조(편집거리 0.35)로 떨어지고,
   그마저 넘으면 환각으로 드롭된다. 1편 돌려 `verify` 절의 `relocated`·`dropped`·
   `fuzzy_match` 비율을 볼 것. fuzzy 가 많으면 **프롬프트를 고친다**(임계를 여는 것은
   6c 를 무력화하는 길이다).

4. **6b 프롬프트가 `earlier`/`later` 를 실제로 내는가.**
   ±60 으로 좁힌 대가를 갚는 통로 전체가 이 어휘에 걸려 있다. 모델이 창 밖일 때 `none`
   으로 답해 버리면 재프로브가 한 번도 안 돌고 좁힌 창이 그대로 벽이 된다.
   ⇒ **개통 조건: `tests/data/v3_exception_labels/` 7편으로 `exception_score` 채점 miss 0**
   (v3 M8 이 그 조건으로 fail 0 이었다).

## 2. 비용·한도 — 값을 갈아끼울 근거

5. **멀티파트 실 과금이 산식과 맞는가.** 첫 실호출의 `usage["prompt"]` 를
   `재생초 × (fps×66 + 25)` 조각 합계와 대조. ⚠ `countTokens` 는 멀티파트를 3.8배 과소
   계산하므로 못 쓴다(기획서 §2-C).
6. **`text_tokens` 환산.** run_log 의 `text_tokens_check`(4단계 추정 vs 6단계 실측 전사
   길이)를 실제 `prompt_token_count` 와 맞대어 `TEXT_TOKENS_PER_CHAR` 를 갈아낀다.
   이 값이 90분 소재의 fps 2 성립 여부를 가른다(기획서 §4).
7. ✅ **thinking 이 출력 예산을 먹는다 — 실측(2026-09-04).** 8단계 모양 프롬프트·예산 4096:
   minimal 0 · low 466 · **medium 2050**(예산의 51%) · high 1397 thoughts. 전부 통과.
   같은 프롬프트를 **512** 로 부르면 thinking 487 · 출력 11 로 **MAX_TOKENS 절단**이 났다.
   ⇒ `FLAG_MAX_OUTPUT_TOKENS = 4096` 은 이 모양에서 여유가 있다. ⚠ medium 이 2050 을
   쓰므로 **프롬프트가 복잡해지면 다시 재야 한다**(V3-M2 절단 사고와 같은 자리).
   6단계 65,536 은 후보 16개 응답으로 아직 안 재 봤다.
8. **`--max-shorts` 실제 승인 편 수 분포.** 비용이 승인 편 수에 곱해진다(O7). 20편 실측
   전에는 기획서 §4 의 k 가 가정이다.
9. **동시 4 가 프로젝트 TPM 을 지나는가.** 429/503 0건은 단일 노드 48콜 실측이고
   **노드 6대 동시는 미검증**이다. 8 로 올리는 것은 AI Studio 실측 뒤.
10. **6b 예산.** `FLASH_BUDGET=8` · 토큰 상한 40만이 실제 소모와 맞는가(기획서 §4 의
    50,000~230,000 은 추정).
11. **긴 소재의 시간.** 3시간 소재 6단계 1콜(타임아웃 450초)·8단계 병렬의 실제 시간·요금.

## 3. 배선 — 실물에서만 드러나는 것

12. **5단계 실경로.** 720p/30fps 인코딩 크기·업로드 시간(추정 2~3분) · Files API 폴링 ·
    48h 만료 재업로드 · 체크포인트의 핸들 문자열을 6·6b·8 이 그대로 쓰는 배선.
13. **실전사.** 이 판은 격자 단어를 주입했다. whisper 실전사의 cue 묶음·저확신 표지가
    6단계 프롬프트와 6c 대조에서 어떻게 도는지.
14. **6b 가 실제로 경계를 옮기는 경로.** 합성 소재(testsrc2)는 장면 전환이 0개라
    프로브가 모델을 안 부른다 — 실소재라야 옮기고 스냅하고 축소 검증까지 돈다.
15. **재시도 분류.** 실제 429 응답에서 SDK 가 `.code` 를 채우는지. 안 채우면 분류 불가로
    떨어져 재시도가 사라진다(조용하지는 않다 — 메시지에 예외 타입이 실린다).
16. **`media_processing=STATIC`.** 기본은 안 보낸다. 켜기 전에 400 이 안 나는지 확인.
    아울러 `requirements.txt` 의 `google-genai>=0.8.0` 을 **핀으로 바꿔야 한다** — 노드마다
    판이 다르면 이 필드가 있는 노드와 없는 노드가 갈린다.

## 4. 판정 품질 — 데이터가 쌓여야 아는 것

17. **§2-E 재검증(160콜).** 이음새 판정 κ 0.44 · hook_weak 12/12 false(분산 0). 기획서가
    '잠정'으로 낮춘 그 항목이다.
18. **후보 다양성.** 5~16개가 정말 서로 다른 아크인가 — funnel 의 IoU 0.5 dedup 이 몇 개를
    지우는지로 간접 확인.
19. **8단계 반려율.** 모델이 `confidence`·`note` 를 습관적으로 얹으면 미채점이 늘고 승인률이
    조용히 떨어진다. `reason="invalid_response"` 비율을 세고, 높으면 **프롬프트를 먼저
    고친다**(검증기를 여는 것은 M9 뒷문이다).
20. **`[저확신]` 임계 0.5.** v3 는 모델 자기신고 확신도에 쓰던 자인데 v4 는 whisper **단어
    확률**이라 척도가 다르다. 표시만 하고 줄을 버리지는 않게 해 뒀다.
