# 티키타카 ↔ v3-human-flow 비교 · 이식 추천 보고서

## 1. 한 줄 결론

두 파이프라인은 **같은 규율(시각은 코드, LLM은 ID만)로 다른 장르를 만드는 형제**이고, 티키타카에 없는 것은 대본 능력이 아니라 **만든 것을 되돌아보는 층** — 컷 내용 검증·사람 확인 산출·캐시 지문·렌더 결정성 — 이며, 그 넷은 전부 값싸게(대개 LLM 호출 0) 이식된다.

---

## 2. 두 파이프라인은 무엇인가

**v3-human-flow (`app/v3/`, `--story-flow human`)** — 롱폼 한 회차를 격자(span·scene_cut·전사 단어·arousal)로 재단하고 Stage 1·2가 영상을 정독해 기록(meaning/span)을 만든 뒤, 그 기록만으로 **리캡 쇼츠 한 편**을 짓는다. 대본은 사람 편집 순서를 그대로 쪼갠 5걸음(주제→씬→대사→내레이션→덮개)이고, 걸음마다 검증기가 형식으로 반려하며 ≤2회 재질의 뒤 소진되면 편이 죽는다. 편의 뼈대는 **내레이션과 그 밑에 깔리는 덮개 화면**이고, 480p 초안을 한 번 렌더해 다시 본 뒤 최종을 굽는 2-pass 구조다. 회차당 N편은 `plan`이 회차 지도 위에서 나눈다.

**티키타카 (`app/tikitaka/`, `python -m app.tikitaka`)** — 드라마 회차에서 **대사 립싱크 쇼츠**를 만든다. 한 호출로 14버전 대본(N=내레이션 / S=대사 / A=현장음 행)을 텍스트로 싸게 펼치고, 재순위 → 상위 N편만 영상 확인 패스 → 테이블(단어 시각·샷 경계·TTS 실측) → 렌더한다. 편의 뼈대는 **대사 그 자체**라 S 행은 전사 단어에 묶여 손댈 수 없고, N 행 길이는 TTS 실측이 마스터다. 권리사 가이드(.md 구조 키: 활용 불가 구간·지양 단어·배우·로고·카피)가 프롬프트와 기계 벨트 3겹으로 들어가 있다.

**목적 차이의 핵심** — v3hf는 *한 편의 구성 완결성*을 형식으로 보장하려 하고, 티키타카는 *회차당 10편 발행*을 값싸게 뽑아 사람 QA로 거른다. 소재는 겹친다(둘 다 「지금 불륜이 문제가 아닙니다」·포핸즈를 실측에 썼다).

## 3. 공통점

1. **시간 정본은 코드다.** LLM은 어느 단계에서도 최종 시각을 내지 않는다 — 티키타카는 `L-`/`S-` ID만(시각은 `bind_dialogue` −0.05/+0.15·`action_window` 샷 경계 nudge·TTS 실측), v3hf는 meaning/span id와 L/G/C 앵커만(시각은 grid lookup·0.30s 스냅). 둘 다 타임스탬프 환각 실사고(티키타카 E1 오차 52s / v3 933초 환각)에서 나온 규율이다.
2. **영상을 정독하는 단계는 한 번뿐이고, 이후엔 국소 창으로만 다시 본다.** 티키타카 3 index(10분 창) ↔ v3 Stage 2(청크). 그 뒤는 기록만 소비하고, 확인 패스·덮개 프로브·프레이밍·라벨 프로브가 좁은 창을 본다.
3. **내레이션 길이는 TTS 실측이 정본이고 화면이 거기 맞춘다.** 티키타카 `_tts_cached` 실측 → 정배속 1.0~2.0s 컷 스택(슬로우 모션 금지), v3hf `measured_sec` → 덮개 창 길이. 계획값(4자/초)은 표기·견적용이다.
4. **같은 화면 두 번 금지를 코드가 강제한다.** 티키타카 `used` 구간·`trim_source`·같은 샷 회피·A/S 중복 3중, v3hf `placed` 점유·B-roll은 고른 씬 안에서만.
5. **텍스트 오버레이는 얼굴을 피해 배치하고, 실패하면 옮기지 않고 기록한다.** 티키타카 `effects.place` ↔ v3hf `label_faces`(위→반대 옆→같은 옆→아래).
6. **레터박스(활성 그림 영역)를 LLM이 아니라 코드가 잰다.** 티키타카 `detect_active_area`(cropdetect 5지점 최빈값) ↔ v3hf `letterbox.py`(16표본 누적 최대 밝기 ≤12). 둘 다 실사고(1920×960 띠)에서 나왔다.
7. **프롬프트 지시만으로는 모델이 안 지킨다는 교훈을 공유하고, 프롬프트와 검증기를 한 벌로 고친다.** 티키타카 재순위 별도 호출(예시 베낌)·`enforce_scene_order`·활용 불가 3겹, v3hf `--exclude-*` 형식 반려·구멍 승격.
8. **조용한 절단·폴백 금지 + 같은 기준의 실패 비대칭.** 권리·계약 위반(활용 불가 컷·검은 컷 / snap<100·exception 유입)은 크게 실패하고, 연출·관찰 보조(프레이밍 중앙 폴백·효과자막 생략 / 프로브·얼굴 회피)는 본편을 막지 않고 건별로 기록한다.
9. **사람이 AI를 이긴다.** 티키타카 CLI 플래그 > 가이드 키, `verified_v{n}.json` 손편집 존중; v3hf `edit_overrides`·`map_overrides`(모르는 값 ValueError). 애매한 판정(두 이름 클러스터 / 인명 내부 변형)은 양쪽 다 자동 교정하지 않고 사람에게 넘긴다.
10. **원응답을 캐시해 규칙만 바뀌면 재호출 0으로 후처리를 다시 돈다.** `verify_raw`+`finalize_from_raw`·framing `_reparse_cached`·agentic raw ↔ watch_trim 컷 재적용·정독 사이드카.
11. **비용 설계와 호출 원장이 같다.** 텍스트로 싸게 여러 판을 펼치고 영상은 좁게 본다. `llm_usage.json` ↔ `run_log.gemini_usage` — 둘 다 USD 환산은 없다.

## 4. 차이점

| 축 | 티키타카 | v3-human-flow | 왜 중요한가 |
|---|---|---|---|
| 대본 생성 방향 | 1콜로 14버전(비선형 10·선형 4)을 펼치고 재순위 → 상위만 영상 확인 | 편 1개를 5걸음으로 좁혀 가며 걸음마다 전용 검증기 | 폭은 선택지 다양성을, 깊이는 편 하나의 구성 결함을 산다. 배타적이지 않다 — 폭을 유지한 채 렌더 대상에만 깊이를 붙일 수 있다 |
| 검증 실패 처리 | 항목 드롭+`issues`, 버전은 살린다. 반려·재질의 루프 없음 | 반려 사유를 실어 ≤2회 재질의, 소진 시 편 실패(폴백 편성 없음) | 드롭은 대본을 조용히 얇게 만든다(v3 "싹 무시해" 0.8s 조각·2화 v5 컷 0개). 14버전 전제에선 합리적이나 추천 버전 안의 드롭은 아무에게도 안 되묻는다 |
| 시각 확정 재료 | S=전사 단어(+무음 연장), A=샷 경계 ±0.1s, N=TTS 실측 컷 스택 | span(0.5s 공백·문장부호·44자·6s) 격자 + scene_cut | 티키타카가 더 정밀하다(립싱크 요구). **v3 방식은 드라마 대사 쇼츠에 그대로 못 쓴다** |
| 내레이션 ↔ 덮개 화면 결합 | N 스키마는 `{type,text,effect}`뿐. 화면은 테이블 단계 agentic(±40s)·인접 샷이 **사후 검색** | 걸음 4가 문장과 함께 화면 id(cover)를 지정, 목록 밖은 무시·전부 밖이면 반려 | 사람 편집자는 문장을 쓸 때 이미 화면을 떠올린다. 티키타카 모델은 지정할 재료(순간 desc)를 이미 보는데 **어휘가 없다** |
| 만든 뒤 보고 되돌아가기 | 없다. 6 render는 곧 완성본이고 덮어쓴다 | draft(480p·hold 반영) → watch_trim(빼기 전용) → Stage 4가 트림된 화면을 봄 → validate | 티키타카에 "만든 것을 보는 눈"이 없다. 다만 N 행은 TTS 길이를 채워야 해서 답은 '빼기'가 아니라 '교체'다 |
| 하류 → 상류 역류 통로 | 없다. `⚠ 미달`·`컷 0개`·드리프트 탈락은 notes로 끝나고 대본은 그대로 | 프로브 모순 → 걸음 4 재질의 1회 → 지도 corrections → story 1회 재실행 | 관측은 티키타카가 오히려 풍부한데(cut_origin·shortfall·drift·black) 소비처가 로그뿐이다 |
| 캐시 판정 | 하류 5곳은 이미 내용 지문. **상류 4곳(transcript·index·rebuild·verified)은 존재 여부만** | 전 단계가 상류 내용 지문(+스키마 버전). 프롬프트 문구는 지문 밖 | 화자 177줄을 고친 뒤에도 옛 리빌딩이 옛 화자로 남는 '조용한 불일치'를 사람이 `--redo`로 기억해야 푼다 |
| 렌더 결정성·산출 보존 | 지문·체크포인트 없음. 루프가 닿으면 항상 재굽고 덮어쓴다(`keep_r9/`·`keep_drift/` 손 백업) | `render_fp` 사이드카 일치 시 스킵 + 재렌더 전 `final_prev_<ts>` 보존 | 수정 전후 대조가 사람 기억과 디렉토리 복사에 걸려 있다. A/B의 계측 전제 |
| 이해 문서 구조 | digest 1콜 자유 서술(cautions는 자유 텍스트라 벨트가 못 읽는다) | 사실/믿음 장부·설정↔회수 레지스터·연출 층위·역방향 소급 | 내레이션이 인물이 '믿는 것'을 사실로 단정하면 편이 거짓이 된다(2화 v10 인과 날조) |
| 화면 글자 재료 | 없다. moments kind = reaction/action/ambience, 1fps·360p 프록시 | Stage 2 `screen_text`(≤300자)/`has_text` + 원본 해상도 정독 패스 | 이 작품의 결정적 증거 절반이 글자(문자·찌라시·기사)인데 인덱스는 "글자가 있었다"만 안다 |
| 연출 층위(상상·회상) | 없다 | `diegesis` 4값 + 훅/결말 게이트 → review | 상상 장면을 결말 선공개형 훅으로 쓰면 제목까지 거짓이 된다 |
| 얼굴·프레이밍 | Gemini에 프레임 3장 → 주인물 좌표·close/two_shot(Haar를 의도적으로 거부) | YuNet/Haar 측정 + 라벨 창 실제 프레임에서 얼굴 검출 | '누가 주인공인가'는 티키타카가 옳고, '지금 어디가 가려지나'는 측정이 옳다 — 역할이 다르다 |
| 사람 개입 형태·보존 | 권리사 계약 방향은 완성(가이드 md). 검수자 교정은 산출물 직접 편집이라 `--redo`에 휘발 | 검수자 교정 방향이 완성(overrides·review.json). 권리사 계약 입력은 없다 | **서로 반대 반쪽을 가졌다.** 티키타카에 필요한 건 '신원 있는 오버라이드'와 '무엇을 봐야 하는가' 산출 |
| 편 간 중복 통제 | 프롬프트 지시 세 곳뿐, 겹침을 재는 코드 0 | `plan`이 편 사이 중복률 >20% 반려, `--exclude-*` 형식 반려 | 회차당 10편 발행인데 상위 10 안에 97% 겹치는 쌍이 실측된다 |
| LLM 예산 상수 | 재시도 회수만 있고 예산 상수 없음(호출이 컷·행 수에 비례) | 단계마다 예산 상수 + 소진 시 동작 명시 | 새 프로브를 얹으면 호출이 컷 수만큼 는다 — 이식할 때 반드시 함께 가져와야 할 규율 |

## 5. 추천 — 우선순위 순

우선순위 기준: **품질 이득 ÷ 난이도 + 지금 아픈 곳.** 1군은 대체로 LLM 호출 0이거나 이미 있는 호출에 얹는 것이고, 뒤로 갈수록 새 호출·새 실측이 필요하다.

### 1군 — 바로 착수

#### ① 렌더 지문 + 이전 산출 보존 (편집자흐름-8) · **S · adapt**
- **v3hf의 무엇**: `pipeline._run_m4` — `render_fingerprint.json` 사이드카가 일치할 때만 스킵, 재렌더 전 기존 최종본을 `final_prev_<mtime>.mp4`로 rename.
- **티키타카 어디에**: 6 `render.render()` 머리·꼬리. 지문 일치 + `out.exists()`면 ffmpeg 미실행, 아니면 기존 mp4를 `prev/` 아래로 옮기고 굽는다. `--redo render`는 mp4가 아니라 **사이드카만** 지우고 `force=True`를 넘긴다.
- **기대 효과**: 수정 전후 대조가 손 백업에서 코드로 내려온다. 아래 모든 후보의 A/B 계측 전제.
- **교정 반영**: ⓐ 지문 재료를 나열하지 말 것 — ASS 문자열·filtergraph·argv(출력 경로 제외, 파일 경로는 자리표시로 치환) + argv가 경로로만 가리키는 파일 해시(TTS mp3·로고·폰트·소스) + ffmpeg 버전 + 규칙 버전 상수. **filtergraph에는 입력 목록이 없다**(`-ss`·TTS 경로는 cmd에만) — 후보가 빠뜨린 TTS mp3·로고가 여기서 들어온다. ⓑ prev 파일명은 **초 단위 + 기존 파일 mtime** 기준(분 단위·현재 시각이면 같은 분 두 번째 라운드에서 충돌). ⓒ 보존 2개 상한은 원본에 없는 추가 규칙 — 삭제 건은 로그에 남긴다. ⓓ 사이드카가 없으면 무조건 렌더(기존 24개 mp4가 전부 여기 해당). ⓔ 시간 절약은 크지 않다(렌더 17~21초/편) — 이득은 **대조**다.
- **순서 근거**: 값이 싸고, 다른 후보의 "고치기 전/후"를 재는 자가 없으면 나머지 실측이 전부 손 백업에 의존한다.

#### ② 사람 게이트 산출 `review_v{n}.json` (구조-4) · **S · adapt**
- **v3hf의 무엇**: `story_flow.review_items` → `pipeline.py`가 `<job>/review.json`(`schema v3_review/v1`)으로 기록. 빈 목록도 파일은 쓰고 발행을 막지 않는다.
- **티키타카 어디에**: CLI 렌더 직후, `publish_v{n}.json` 저장과 같은 블록. 새 `review.py`의 순수 수집 함수. kind 어휘를 v1에서 동결: `script | guide | speaker | cuts | effect | framing`.
- **기대 효과**: 지금 6곳(issues·character_flags·guide_hits·table notes·effects 생략·framing ok:false·voice_check ambiguous)에 흩어진 ⚠·⚠⚠가 버전당 한 파일로 모인다. 검수자가 렌더를 보기 전에 어디를 볼지 안다.
- **교정 반영**: ⓐ v3hf의 review.json은 **잡당 1개**(잡=편 1개) — "버전별"은 티키타카 각색이다. 파일을 쓰는 곳도 `build_story_doc`이 아니라 pipeline이다. ⓑ **인물 의심 잔존 `⚠⚠`는 `issues`에 없다** — `version["character_flags"]`와 stdout 로그에만 있으므로 수집기가 두 필드를 다 봐야 한다. ⓒ **드리프트는 notes에 안 남는다**(`trim_source`가 소스를 조용히 버린다) — drift kind를 넣으려면 ③이 선행이다. ⓓ "6.5 발행 메모 단계"라는 번호 단계는 없다(렌더 직후 인라인 저장). ⓔ 효과자막 생략 사유는 캐시에 없다 — v1은 '생략됨' 사실만.
- **순서 근거**: LLM 호출 0·위험 0이고, 아래 ③·⑤·2군 후보들이 전부 여기로 출구를 낸다. 먼저 있어야 뒤의 것들이 흩어지지 않는다.

#### ③ 컷 출처·드리프트 재감사 벨트 (품질벨트-2) · **S · adapt**
- **v3hf의 무엇**: `verify_time_alignment`·`verify_edit_plan` — 산출 시각이 100% 격자에서 왔는지 사후에 재확인하고, `pipeline`이 pct<100이면 AssertionError.
- **티키타카 어디에**: `table.py`에 순수 함수 둘 — `cut_authority(src)`(접두사 `AG-`/`L-`/`SC`/`S-`로 출처 판별)와 `audit_cut_drift(rows, proposals)`. 배선 둘: 캐시 재사용 경로(`cuts_in_black` 옆)는 **자동 재생성**, 생성 경로는 N 행 위반 시 RuntimeError(A 행은 메모).
- **기대 효과**: 2026-09-12에 사람이 임시 스크립트로 한 24편 판정이 코드로 내려온다. **지금도 드리프트 >3s 컷 10개가 4개 테이블에 남아 있다**(포핸즈 v1 + 1화 `_r0300-0700` 태그 3편 — 09-12 스윕이 무태그 12편만 돌려 정확히 놓친 집합, 최대 +21.8s).
- **교정 반영**: ⓐ `cut_origin`은 **이미 있다**(행 단위 `agentic|index`) — 문제는 보충 컷이 섞여도 행 전체가 `agentic`으로 찍히는 것. 새 `authority` 키를 만들면 옛 테이블이 감사 밖으로 빠지므로 `src` 접두사 파싱으로 간다(실측 분포 proposal 427·word 289·fill 23·moment 4). ⓑ 후보의 규칙 ②(모든 in/out이 샷 경계 ±0.1s 비접촉)는 **기각** — 정상 컷 36개가 접촉한다(`stack_cuts` 분할·짧은 샷·min_sec 늘림 분기). 하드페일로 켜면 멀쩡한 편이 죽는다. ⓒ 규칙 ③(S 단어 시각 범위)은 289/289 통과 — 정보량 0이라 stale 판정용으로만. ⓓ **선행 필수**: `carve_black`이 `trim_source(..., max_drift=inf)`로 부른다 — 이 한 줄을 고치지 않고 벨트를 켜면 검은 화면 깎기가 만든 드리프트로 정상 편이 생성 중에 죽는다. ⓔ 저장된 컷에 `prop_out`이 없다 — 컷 dict에 싣거나 agentic raw 캐시에서 복원해야 사후 측정이 성립한다. ⓕ 캐시 위반 조치는 RuntimeError가 아니라 자동 재생성(옛 캐시는 가드 이전 산출이지 버그가 아니다).
- **순서 근거**: 드라이런 스크립트가 이미 있고 결함이 지금 남아 있다. 재생성 대상 4편·편당 ~30초·agentic 호출 0.

#### ④ 상류 캐시 판정을 내용 지문으로 (구조-6) · **S · adapt**
- **v3hf의 무엇**: `_run_m2` 청크 캐시 = sha1(계획+span+스키마 버전), `_fp_payload`(프롬프트 문구는 지문 밖, 스키마 버전은 안).
- **티키타카 어디에**: 상류 4곳만. `transcribe()`가 `backend` 대조, `index.json`에 `transcript_sha`(줄 id+text, 화자 제외), `rebuild.json`에 `material_sha`, `verified_v{n}.json`에 그 버전 초안의 `draft_sha`. 기본은 **재사용 + ⚠ 로그 + run_log 기록**(회귀 0), `--strict-cache`일 때만 폐기.
- **기대 효과**: "고쳤는데 왜 그대로지"가 보이게 된다. 토큰 0·시간 ms.
- **교정 반영**: ⓐ 프레이밍이 과장됐다 — 티키타카 하류 5곳(digest·table·agentic·effects·scenecut/blackspans)은 **이미 내용 지문**이다. 범위는 상류 4곳 + `REDO_ORDER`. ⓑ `transcript.json`에 `backend`·`model` 키는 **이미 있다** — 빠진 건 대조뿐이라 `stt_model`·`source_sha` 추가는 불필요. ⓒ 새 해시를 짜지 말고 `digest_sha`를 재료 정본으로 재사용한다. ⓓ **rebuild 지문에 화자를 넣고 strict로 폐기하면 순환이 생긴다** — `verify.apply_speaker_fixes`가 자기 상류(transcript)를 되쓰므로 rebuild 재생성 → verify 재호출(편당 10~26만 토큰)이 반복된다. 화자 델타는 **어느 모드에서도 경고 전용**(두 겹 sha로 분리). ⓔ verified의 sha는 **그 버전 초안 항목만** — 전체를 해시하면 `--rerank verified`마다 전 버전이 stale로 찍힌다. ⓕ 실구멍 추가: `--redo transcribe/index`가 `voice_check.json`·`diarize_windows/`를 안 지워 재전사 뒤 화자 교정이 조용히 빠진다. `REDO_ORDER`에 `scenecut`·`voice_check`를 넣으며 같이 닫는다. ⓖ v3도 전사는 존재 캐시다 — 이건 'v3 이식'이 아니라 둘 다 안 한 것을 새로 하는 항목.
- **순서 근거**: 해시뿐이라 사실상 공짜이고, ②의 review에 stale 사유를 실을 자리가 생긴다.

#### ⑤ 버전 간 재료 중복률 기계 검사 (구조-7) · **S(①②) + M(③) · adapt**
- **v3hf의 무엇**: `plan.validate_plan` — 편 사이 meaning 중복률(작은 쪽 기준) >0.20 반려, `select.excluded_meaning_ids`(겹침 ≥0.5 형식 반려).
- **티키타카 어디에**: 4 rebuild 검증 뒤·재순위 앞에 순수 함수 `version_overlap_matrix`. 소비 셋 — (1) `RERANK_PROMPT`에 겹침 표 주입(초과 쌍 없으면 빈 문자열 = 프롬프트 바이트 동일), (2) CLI 상위 N 선정에서 `ranking[:count]` 대신 `select_distinct`, (3) 여분이 모자라 못 푸는 쌍은 **상대 버전 구간을 `extra_exclude`로 넣어 그 버전만 재리빌딩**(기존 `--range` 여집합 배제 기계 재사용, 텍스트 1콜).
- **기대 효과**: 회차당 10편 발행에서 같은 장면을 두 번 내보내는 것을 막는다. 실측 — 1화 상위 10 안 `v8–v13 97%`(사실상 같은 편)·`v2–v7 64%`, 2화 `v9–v13 87~89%`, 3화 상위 4 안 `v1–v7 72%`·`v2–v13 52~58%`.
- **교정 반영**: ⓐ 프롬프트 지시는 한 곳이 아니라 **세 곳**이다(제1원칙·출력 스펙·재순위 ④) — 그래도 실패한다는 것이 요점. ⓑ "6회 중 4회"는 `--exclude` 실패 횟수가 아니라 *지도 없는 plan의 주제 쏠림* 실측이다. ⓒ v3 중복률은 meaning **id 집합** 기준 — 티키타카는 초 기준 번역이 맞다. ⓓ **각 버전 구간을 먼저 union 해야 한다**(안 하면 A 순간이 S 줄과 겹쳐 비율 1.04가 나온다). ⓔ "선형 11~14끼리 예외"는 **`--range` 실행에만** 타당하다 — 일반 실행의 큰 겹침이 바로 선형↔비선형 쌍이고 3화 `v1–v14`는 100%다. ⓕ v3의 반려·재질의는 가져오지 않는다(한 호출 14버전이라 반려 = 전량 재생성). ⓖ 임계 0.2는 느슨하지 않다 — 첫 실측에서 0.3과 나란히 찍어 확정한다.
- **순서 근거**: 순수 계산이고 실측 증거가 이미 있으며, 발행 단위 결함에 직결된다.

#### ⑥ N 행 컷 내용 모순 판정 (구조-1) · **S~M · adapt**
- **v3hf의 무엇**: `story_flow/cover.run_probe`·`PROBE_PROMPT` — 덮개 창을 잘라 Flash에 문장과 함께 보내 `text_matches:bool`·`seen`을 받고, false면 되돌림 ≤1회(`COVER_REASK_MAX`).
- **티키타카 어디에**: **새 단계를 만들지 않는다.** 5.5 `framing`이 이미 컷마다 프레임 3장(20/50/80%)을 **내레이션 문장 + 컷 desc 문맥과 함께** 보내고 있다 — 그 응답에 N 행 한정 `matches`·`seen` 두 칸을 얹으면 추가 호출 0이다(v3hf가 start_sec 프로브에 얹은 것과 정확히 같은 규율). 교체가 필요하면 그 행의 컷을 `rejected`로 두고 **`build_table` 안에서 테이블을 통째로 재조립**한다.
- **기대 효과**: 문서가 스스로 남긴 마지막 caveat("남은 어긋남은 N 행 컷 내용 — 컷 탐색 품질은 별건")을 닫는다. 「[혈압 상승]」 밑 포옹 컷 유형.
- **교정 반영**: ⓐ v3hf의 `text_matches`는 **독립 검사가 아니라 start_sec 프로브의 부산물**이고, 창 여유 ≥1.0s인 덮개만 판정을 받는다(hold·stack·산술 덮개는 판정 없음) — "N 행마다 본다"는 커버리지가 아니다. ⓑ **되돌림 방향이 반대다** — v3hf는 *걸음 4의 내레이션 문장을 재질의*한다. 티키타카에서 N 문장은 확인 패스·가이드·배우 표기 벨트가 확정한 정본이고 TTS 실측이 마스터라 문장을 고치면 지문 연쇄가 통째로 무효다. **컷을 바꾸는 쪽이 맞고, 그건 이식이 아니라 새 설계다**(출처를 그렇게 적어야 한다). ⓒ 예산 상수는 `cover.FLASH_BUDGET=10`(refine의 8이 아니다). ⓓ `temperature 0`은 티키타카 `llm.py` 규약(샘플링 파라미터 미사용·thinking_level만)과 어긋난다 — 쓰지 않는다. ⓔ 새 5.2 단계는 자리가 틀렸다 — `build_table`이 `fill_n_rows` 뒤에 벨트·t0를 돌리고 저장하므로, 저장 뒤에 컷을 바꾸면 벨트·t0를 다시 돌려야 한다. **`fill_n_rows` 직후·벨트 앞**이 맞다. ⓕ **부분 교체 금지** — `used`/`used_shots` 누적 상태를 깨뜨린다. `reject` 인자 + 재조립이어야 겹침 0·같은 샷 회피·드리프트·검정·활용 불가가 전부 다시 걸린다. ⓖ "재선택 컷은 그 구간만 재호출"은 framing엔 맞고 **effects는 틀리다** — 키가 `i|effect|cuts[0].in|t0`라 둘째 이후 컷 교체는 무효화되지 않고, t0가 밀리면 뒤 행까지 재계산된다. ⓗ 근거 사례는 09-12 드리프트 수정으로 **일부 이미 닫혔다** — 그래서 첫 판은 `audit` 모드(판정·기록만, 컷 불변)로 1·2화 캐시 테이블의 모순율과 정밀도를 먼저 재고, 정밀도 ≥0.8·모순율 ≥5%일 때만 교체를 켠다.
- **순서 근거**: 지금 가장 아픈 곳이지만 교체 루프의 가치가 미증명 — 이미 있는 호출에 필드 두 칸을 얹는 감사부터라 착수 비용은 1군 수준이다.

#### ⑦ 잡 단위 `overrides.json` — 사람 교정을 산출물 밖에 (구조-5) · **S~M · adapt**
- **v3hf의 무엇**: `episode_map.apply_overrides` — `map_overrides.json`을 로드 직후 병합하고, 캐시가 맞아도 다시 얹어 저장. 모르는 id·값은 ValueError.
- **티키타카 어디에**: `<job>/overrides.json` = `{schema, speakers{L-id:이름}, voice_clusters{g:speaker_N:이름}, versions{n:{label_suffix, drop_items}}}`. 배선 셋 — voice_check 직후(캐시 여부 무관 매번), `verify.apply_speaker_fixes` 직후(사람 > 모델), 캐시 대본 벨트 맨 앞.
- **기대 효과**: 3화 화자 뒤바뀜 교정(137줄)·`(전화)` 접미가 `--redo`를 넘어 살아남는다. 지금은 `voice_relabel` 키를 **코드가 읽지 않고**, `--redo index` 한 번에 증발한다.
- **교정 반영**: ⓐ 소스의 `names{틀림:맞음}`는 **저장만 하고 소비자가 없다**(v3hf의 '읽지 않는 기록 키') — 완성된 메커니즘이 아니다. 티키타카는 기존 `apply_name_map`·`build_ass(name_map=)`에 합쳐야 하고 새 치환기를 만들면 안 된다. ⓑ 소스는 **멱등이 아니다**(사람 register 항목을 실행마다 append) — 멱등을 테스트로 박는다. ⓒ `overrides.py`(edit_overrides)는 성격이 다른 편집실 페이로드 수용기다 — 근거는 `map_overrides` 하나로 충분. ⓓ `diegesis`는 티키타카에 소비자가 없어 이번 범위 제외. ⓔ 줄 ID만으론 3화 교정이 137줄 나열이 된다 — **`voice_clusters` 키**가 있어야 두 줄로 표현된다. ⓕ **지문 재료에 overrides sha를 넣지 말 것** — `digest_sha`는 이미 줄별 화자를, `table_matches_version`은 S 행 화자를 본다. `rows_fingerprint`에 넣으면 agentic 컷 캐시가 통째로 무효화된다. 진짜 빠진 것은 `table_matches_version`의 **`label_suffix` 비교 한 줄**. ⓖ `REDO_FILES`는 지울 패턴 화이트리스트라 overrides.json은 애초에 안 지워진다 — 할 일은 '제외'가 아니라 '로드 직후 매번 재적용'. ⓗ 곁다리 구멍: `--redo index` 뒤 `voice_check.json`이 안 지워져 목소리 교정이 조용히 빠진다(④와 한 커밋).

#### ⑧ 전사 표기 내부 불일치 신고 (품질벨트-5) · **S · adapt(범위 대폭 축소)**
- **v3hf의 무엇**: `textcheck.check_internal_variants`/`fix_internal_variants` — 같은 인물의 표기 흔들림을 편 전체에서 찾아 신고. LLM 0콜·결정적.
- **티키타카 어디에**: 신설 `transcript_check.py`, **1.6단계(polish 뒤 · index 앞)**. 이 레포에 이미 `app/v3/textcheck.py`가 있으니 import 재사용.
- **기대 효과**: 실측 — 1화 「류지수」7회 ↔ 「유지수」2회, 2화 4↔1. 이 이름은 `--cast`·가이드 어디에도 없는 조연이라 keyterms도 `check_names`도 원리적으로 못 잡고, polish는 창 단위라 편 전체 통일 개념이 없다(2화는 고치고 1화는 안 고쳤다). 립싱크 S 자막은 줄 text를 그대로 그리므로 곧바로 발행된다.
- **교정 반영**: ⓐ **채택은 내부 변형 하나뿐.** `check_names`(사전 대조)는 4편에서 적중 0·오탐 2~3(「초대해 주셔서」→주민서, 「알았지?」→임예지) — 자동 교정하면 립싱크 자막에 "임예지?"가 나간다. `check_repetition`(반복 환각)은 검출 7건이 **전부 정상 리액션 대사**(어?×8·아!×7)라 거절. ⓑ **`_PERSON_MARKER`에 `\s?` 한 글자를 넣지 않으면 티키타카에서 0건이다**(Scribe는 "유지수 씨"처럼 띄어 쓴다) — 이식의 핵심 수정이 이것 하나. ⓒ "words[word_i].text도 같이 고쳐 립싱크 유지"는 근거가 틀렸다 — 화면에 나가는 것은 **줄 text**이고 v3hf도 words를 안 고친다. ⓓ **`text_orig` 키를 쓰면 안 된다** — polish의 원문 복원 근거를 덮는다. 별도 키·별도 redo 스텝. ⓔ 자리는 "scenecut 앞"이 아니라 "index 앞"(scenecut은 이미 앞에서 돈다). ⓕ `suggest`가 None(둘 다 사전 밖)이면 **절대 자동 교정 금지, 다수결 금지** — 1화는 다수파가 정답이지만 v3hf EP01에서는 다수파가 오답이었다. ⓖ 조사 중 나온 별건: 진짜 환각의 서명은 텍스트 반복이 아니라 **길이 0초 줄**(2화 L-365~371이 전부 `start==end`)이다.

#### ⑨ 이해 문서에 '믿음' 열 분리 (편집자흐름-7) · **S · adapt(beliefs만)**
- **v3hf의 무엇**: `episode_map` 정방향 패스의 `beliefs_ledger`(holder·confirmed) — 사실과 인물이 믿는 것을 다른 열에 둔다.
- **티키타카 어디에**: 3.7 digest 출력 스키마에 `beliefs[{holder,text,confirmed,ids,resolved_by}]` 추가(+`SCHEMA` 상수를 `digest_sha`에 섞어 캐시 자동 무효화), `digest_block`에 절 하나 + 규칙 한 줄, `rebuild.belief_assert_flags` → `polish_beliefs`(기존 `polish_character_names`와 같은 형식·드롭 없음).
- **기대 효과**: 2화 v10 「의뢰→납치→사고」 날조 유형. 재료는 이미 있다 — 2화 digest의 cautions가 그 왜곡을 스스로 적고 있다. **구멍은 재료가 아니라 기계가 읽을 구조가 없다는 것**이다(cautions는 자유 텍스트).
- **교정 반영**: ⓐ **facts 장부(40건)는 빼라** — 리빌딩·확인 패스가 이미 `source_script`(2화 40.6k자) 전체를 보므로 재나열이고 프롬프트만 는다. ⓑ **register + 패턴 15「대비형」은 보류** — v3hf 실런 발견율이 골든 3연결 중 1건이고 티키타카 소재 실측은 0건인데, 14→15 버전은 확인 패스·agentic·프레이밍·효과자막·렌더 전 하류에 곱해진다. ⓒ v3hf에서 beliefs는 **프롬프트로 주입되지 않는다** — 이 벨트는 이식이 아니라 신설이므로 드롭 금지·기록 전용으로 시작한다. ⓓ `confirmed`는 v3hf에서 역방향 패스가 채운다 — 티키타카엔 역방향이 없으니 정방향 1콜에 받고, 벨트 대상은 **`confirmed=false`(작품이 명시적으로 번복한 믿음)로 좁힌다**(null까지 넣으면 오탐 폭증). ⓔ 판정을 어절 겹침으로 하면 오탐이 크다(쇼츠 내레이션은 원래 인물 시점을 빌린다) — holder 이름 + 내용어 2개 이상 + **믿음 표지 부재**의 합으로. ⓕ 인용문(`quote`)을 모델이 적게 하지 말 것 — ID만 받고 텍스트는 전사에서 코드가 붙인다. ⓖ 오탐률은 **호출 0으로 먼저 잰다**(캐시된 42편 대본에 플래그만 오프라인 실행) — 30% 넘으면 polish를 붙이지 않고 표시만 남긴다.

#### ⑩ 화면 글자 판독 (구조-2) · **M · adapt**
- **v3hf의 무엇**: Stage 2 `screen_text`/`has_text` + `screen_text.py` 정독 패스(원본 해상도 프레임 1~3장, 2s 클러스터, 10분당 4콜, 초벌 힌트 "베끼지 말고 확인", 실패는 초벌 유지).
- **티키타카 어디에**: 3 `INDEX_PROMPT` moments에 `text_screen` kind 추가(+`_KINDS` 등록) + 신설 3.8 정독 패스(index → digest 사이). 원문은 **desc 자체**에 `📄「…」`로 써 넣는다 — `source_script`·digest·verify·N 컷 후보가 코드 무변경으로 받고, 📄가 없으면 프롬프트 바이트가 동일하다.
- **기대 효과**: 실측 — 1화 11·2화 8·3화 11개 순간이 문자·찌라시·기사 화면을 **언급만** 한다(내용 0). 지금 대본은 그 장면을 "충격적인 문자" 이상으로 못 쓴다.
- **교정 반영**: ⓐ 후보가 인용한 "span 1,366 중 104·18장면"은 실측(104)과 **발주 합격 기준**(18장면)을 섞었다 — 실제 실행 기록은 13조각 → 11장면·호출 11/24·채움 6. ⓑ **`--redo index` 없이는 기존 4개 잡에 한 글자도 안 붙는다** → desc 정규식 다리(문자|카톡|찌라시|기사|알림…)를 함께 둬야 재인덱스 없이 붙는다. **3화는 재인덱스 금지**(수동 화자 교정이 `build_index`에 덮인다). ⓒ `parse_window_result`가 desc를 `[:60]`으로 자른다 — kind별로 120까지 넓혀야 원문이 산다. ⓓ `digest_sha`가 이미 moment desc를 해싱하므로 "지문 재료에 포함"은 자동 충족. ⓔ 360p/1fps 스캔 프록시에선 초벌 판독이 사실상 불가하다 — 방어선은 '초벌 유지'가 아니라 **원본 해상도 + 판독 불가 표기 + readable=false 시 desc 불변**이다. ⓕ 소스의 `hold`(정지 화면 승격)는 안 가져온다 — 대신 글자 컷이 1.0~2.0s 스택으로 지나가면 `[읽기 시간 부족]` 메모(조용한 송출 금지). ⓖ 효과자막 지시형 벨트는 실측 근거가 없어 프롬프트 한 줄로 대체.

#### ⑪ 라벨 얼굴 회피를 추정에서 측정으로 (품질벨트-6) · **M+ · adapt**
- **v3hf의 무엇**: `label_faces.py` — 라벨 창의 실제 프레임(5%·50% 지점)에서 얼굴을 검출해 캔버스 좌표로 환산하고 위→반대 옆→같은 옆→아래로 옮긴다. 못 옮기면 유지+기록.
- **티키타카 어디에**: 6 `render()` 안 `build_ass` 직전(로고·카피·안전영역이 들어간 **실제 레이아웃**이 확정된 자리) 또는 5.6 effects 안. 신설 `effect_faces.py`.
- **기대 효과**: 현행은 정밀도 문제가 아니라 **가로 좌표계 오류**다 — `effects.place`는 얼굴 x를 캔버스 비율로 해석하는데 `frame_at`이 주는 값은 소스 정규화 좌표이고, 렌더 크롭이 바로 그 점을 화면 중앙에 놓는다. CLAUDE.md의 반복 땜질(26%가 이마를 덮는다 / 62%가 대사 블록과 겹친다)이 그 증상이다. 세로는 지금도 맞다.
- **교정 반영**: ⓐ **YuNet은 지금 안 돈다** — onnx가 스냅샷·워크트리 어디에도 없고 실행 venv에 cv2도 없다. 실효 검출기는 cv2 내장 Haar이고, onnx 번들·opencv 설치가 선행 작업이다(없으면 종전과 **바이트 동일**이 게이트 조건). ⓑ `label_faces`는 `reframe`의 검출기를 쓰지 않는다(cv2.FaceDetectorYN 직접 + cv2 내장 캐스케이드 폴백). ⓒ **`LABEL_H_RATIO 0.75`는 반높이**(전체 size×1.5) — 그대로 "높이 size×0.75"로 구현하면 박스가 절반이 되어 겹침을 놓친다. 폭은 `place`와 같은 자를 써야 실제 렌더와 맞는다. ⓓ 후보 순서는 4개가 아니라 **5개**(`above-here` 누락 — 열을 안 바꾸고 위로만 올리는 가장 보수적 후보). ⓔ **환산 위험은 설계로 없앨 수 있다** — 렌더의 클립 필터를 공유 함수로 뽑아 **캔버스 공간에서 프레임을 뜨면 환산 코드가 0줄**이다(`crop_x_expr_segs`는 식 문자열을 돌려주므로 "같은 함수로 계산"은 애초에 불가). ⓕ "체크포인트 없음·매 렌더 재계산"은 티키타카 재렌더 관행(24편 전량 재생성)과 어긋난다 — effects 캐시와 **분리된** 별도 지문 캐시로. ⓖ 무료 선행: 검출 0인 폴백 경로의 좌표계도 10줄로 고쳐진다.

### 3군 — 나중

#### ⑫ 연출 층위(diegesis) 필드 + 훅/결말 경고 (구조-3) · **S · adapt**
- **v3hf의 무엇**: Stage 2 `diegesis` 4값 + `select.validate_beats`의 hook/climax note·`diegesis_flags` → review.
- **티키타카 어디에**: `INDEX_PROMPT` scenes **와 moments**에 `diegesis`(기본 actual은 키 생략 → 전부 actual이면 파일 모양 종전과 동일), digest 출력에 `diegesis_final`(전체를 보는 1콜이 v3의 정/역방향 2패스를 대신), `validate_versions`에서 훅·결말이 비actual이면 `[층위 의심]` issue(드롭 아님) → ②의 review.
- **교정 반영**: ⓐ v3 EP01 카페 장면의 실측 라벨은 **recalled**(imagined 아님)이고, **역방향 패스는 diegesis를 하나도 안 바꿨다**(변경 0) — 2패스 이식은 가치 미입증. ⓑ hook/climax 게이트가 실제로 발동한 적은 없다(review 0건). ⓒ 후보의 `[층위 단정]` 기계 판정은 **v3hf에 없다**(프롬프트 문구 한 줄뿐) — 신규 발명이라 오탐이 크니 빼거나 약한 힌트로. ⓓ `digest_sha`에 **스키마 상수를 넣지 않으면** 새 필드가 영원히 빈 채 옛 digest가 재사용된다. ⓔ 인덱스가 10분 창·1fps·LOW라 v3(480p/10fps)보다 단서가 약하다 → unclear 편향을 프롬프트로 강하게. ⓕ **이 작품에 상상 장면이 있는지 자체가 미확인** — 첫 실측이 그 확인이어야 하고, 하나도 없으면 필드만 남기고 다음 작품에서 다시 잰다.
- **순서 근거**: 값은 싸지만 이 소재에서 결함이 발생한다는 증거가 아직 없다.

#### ⑬ 내레이션이 덮을 화면을 대본이 지목 (편집자흐름-1) · **S~M · adapt(형태 변경)**
- **v3hf의 무엇**: 걸음 4가 문장과 함께 `cover` 화면 id를 내고, 덮개 선택에서 지정 창이 0순위.
- **티키타카 어디에**: N 항목 어휘에 **`about`(순간 id 1개)** — '소스 지정'이 아니라 **검색 앵커**다. 주 소비처는 agentic 검색 창을 이웃 ±40s에서 **앵커 ±25s ∪ 이웃**으로 좁히는 것이고, 후보 목록에는 agentic이 실패한 행에만 넣는다.
- **교정 반영**: ⓐ **"화면에 없는 말이 형식상 막힌다"는 과장** — v3hf 검증기는 빈 `cover`를 그냥 통과시키고, 개수 1~3·연속성도 코드가 검사하지 않는다. ⓑ **0순위 티어는 금지** — `fill_n_rows`의 티어는 09-12·09-13 사용자 지적으로 하나씩 박힌 값이라(같은 샷 회피·리드인 장면 우선·드리프트 3s) 그 위에 얹으면 수정들이 무력화된다. ⓒ **L- 지정을 열지 말 것** — 말하는 입이 무음으로 내레이션 밑에 깔리는 새 결함이 생긴다. S-(순간)만. ⓓ **`rows_fingerprint`에 반드시 포함** — 프롬프트에 실리는 값이 지문에 없으면 옛 agentic 제안이 조용히 재사용된다(후보 원문은 "지문 그대로"라고 적었다 — 정면 위반). ⓔ 실측상 **공급 부족은 없다**(N 행 159개 중 컷 0개·미달 0건, 96.9%가 agentic 제안 그대로) — 구멍은 검색 창의 중심이 문장의 주어가 아니라 이웃 대사라는 것. ⓕ index moments 밀도가 스펙의 1/3(장면당 2~2.5)이라 **0단계 게이트 선행**: 리드인 장면 안 미사용 순간이 2개 미만이면 이 항목을 내리고 moments 밀도부터 고친다.
- **순서 근거**: ⑥이 같은 결함을 사후 판정으로 먼저 잡는다 — ⑥의 감사 결과를 보고 사전 예방이 필요한지 정한다.

#### ⑭ 초안 시청 게이트 (편집자흐름-3) · **M~L · adapt(첫 판 기록 전용)**
- **v3hf의 무엇**: `stage4.render_draft`(480p·hold 반영해 초안 시계 = 최종 시계) → `watch_trim`(Flash가 초안을 보고 **빼기 전용** 제안, 안쪽 스냅·20% 상한·pre/post 지문 재적용).
- **티키타카 어디에**: 5 table 뒤·5.5 framing 앞(5.2). 모델은 **행·컷 인덱스만** 지목하고 `{"swaps":[{row,cut,why}]}`만 받는다. S 행은 표에서 아예 뺀다. 배제 목록 + `build_table` 재조립으로 교체. 첫 판은 `report` 모드(테이블 불변).
- **교정 반영**: ⓐ `MAX_CUTS 3`은 조건부다(예산 판 6이고 그 판에선 "빈 배열이 정답"이 뒤집힌다). 안쪽 스냅만도 아니다(`free_zones`·`snap_free`). 예산 산술 벨트도 누락됐다. ⓑ **초안에 TTS는 안 섞인다** — v3hf 모델은 내레이션을 못 듣고 재료표 텍스트로만 안다. 티키타카 초안에 TTS 믹스를 넣는 것은 재사용이 아니라 신규 작업이고 비용도 오른다. ⓒ `render()` 재사용도 성립하지 않는다(height 인자 없음·ASS를 항상 굽는다). ⓓ **교체·축소는 v3hf에 대응물이 없다**(watch_trim은 빼기 전용, `absorb_slivers`·`remap_*`는 이식 대상 아님). ⓔ **초 단위 제안을 받으면 안 된다** — 티키타카엔 span 격자가 없어 모델 산 초를 검증할 수단이 없다. ⓕ 캐시 파급이 양방향으로 틀렸다 — 둘째 이후 컷 교체는 effects 캐시를 **무효화하지 않고**(조용한 불일치), A 행 축소는 t0 체인을 밀어 **전량 재호출**된다. framing도 구간 키라 재호출. ⓖ **A 행 축소는 첫 판에서 뺀다**(승인본 시각이 움직이고 publish 메모까지 밀린다). ⓗ 초안이 못 잡는 항목(자막 폭 초과·화자 오표기)을 게이트 근거로 쓰면 안 된다. ⓘ "초안은 최종의 1/3" 근거 없음 — 비용은 해상도가 아니라 컷 수·seek이 지배한다. ⓙ **⑥(framing 확장)이 같은 질문을 렌더 0회로 묻는 더 싼 안이다** — 같은 편에서 재현율을 비교해 ⑥이 80%에 근접하면 초안 렌더는 버린다.
- **순서 근거**: 가장 비싼 형태의 검증이고, ⑥이 그 이득의 대부분을 먼저 가져갈 수 있다.

## 6. 기각·보류

- **구조-8 프레임 정수 고정(tpad→end_frame)** — **반박**: v3hf의 단조 드리프트(13조각 13프레임·0.3s)는 렌더 체인에 `fps` 필터가 없어 생긴 것이고, 티키타카는 세그먼트 앞에 `fps=30`이 있어 오차가 **±부호 혼재 랜덤워크**다(완성본 43편 실측 −0.007~+0.118s, 중앙 +0.04s, 음수 4편 — ceil 모델은 관측과 불일치). 립싱크는 대사 오디오가 자기 세그먼트로 concat되어 컷 안에 잠기므로 애초에 안 흔들리고, 흔들리는 것은 자막·TTS가 **함께** 최대 0.12s 선행하는 것뿐이다. 대가는 승인된 완성본 44편의 픽셀 변경 + effects·agentic 캐시 전량 무효. → **보류(later)**. 발동 조건만 박제: 컷 25개 이상 편에서 0.15s 초과가 재현되거나, 출력·소스 fps 조합이 바뀌어 단조 누적으로 돌변할 때. 지금 할 일은 렌더 뒤 **비디오 스트림 길이 − table total로 드리프트를 항상 기록**하는 감시 한 줄(픽셀 불변·비용 0).
- **품질벨트-5의 `check_names`(사전 대조)** — **반박**: 4편 전사 실측 적중 0·오탐 2~3. 티키타카는 Scribe keyterms로 사전 이름을 이미 주입하므로 "사전에 있는 이름은 잘 나오고 못 나오는 건 사전에 없는 이름" — 구조적으로 헛그물이다.
- **품질벨트-5의 반복 환각 그물(`check_repetition`/`drop_repetition`)** — **반박**: 4편 검출 7건이 전부 정상 리액션 대사(「어?」×8·「아!」×7·「너무 좋아요.」×3). 드롭 연결은 실제 대사를 버린다.
- **편집자흐름-7의 사실 장부(facts 40건)** — **반박**: `source_script`(2화 40.6k자)가 이미 전 대사·화자·순간을 준다. 판정이 아니라 발췌라 새 정보가 0이고 프롬프트만 는다.
- **편집자흐름-7의 레지스터 + 패턴 15「대비형」** — **보류**: v3hf 실런 발견율이 골든 3연결 중 1건, 티키타카 소재 실측 0건. 14→15 버전은 확인 패스·컷 검색·프레이밍·효과자막·렌더에 곱해지고, 대비형은 수십 분 떨어진 두 장면을 오가는데 `fill_n_rows`·`enforce_scene_order`는 "한 장면 연속"을 전제로 튜닝돼 있다. 값싼 선행 실측(digest.md에 표로만 출력)으로 쓸 만한 쌍이 3편 합계 5건 이상 나올 때만 연다.
- **편집자흐름-1의 0순위 티어 · L- 지정** — **반박**: 티어는 사용자 지적으로 박힌 값이라 위에 얹으면 같은 샷 회피·리드인 장면 우선이 무력화되고, L- 지정은 립싱크 정체성을 깬다. 앵커 형태로만 채택.
- **편집자흐름-3의 A 행 축소** — **보류**: t0 체인을 밀어 effects 전량 재호출 + 승인본 시각 이동 + publish 메모 변경. N 컷 교체의 효과가 실측된 뒤 별건.
- **구조-2의 `hold`(정지 화면 승격)** — **보류**: 렌더 변경이라 별건. 대신 `[읽기 시간 부족]` 메모로 사실만 남긴다.

## 7. 이식하지 않아도 되는 것 (목적 차이)

| 항목 | 왜 안 맞는가 |
|---|---|
| **span 격자 시각 확정 체계** | v3는 0.5s 공백·문장부호·44자 단위 span이 유일한 눈금이다. 티키타카 S 행은 **단어 시각 립싱크**가 정체성이라 더 정밀하고, 격자로 내리면 입과 자막이 어긋난다 |
| **어절 자막·`textcheck` 교정 6단** | 장르 문법이 다르다(예능 어절 자막 vs 드라마 줄 자막). 게다가 티키타카 `polish`는 **오디오를 실제로 듣고** 고치고 `voice_check`는 diarize 증인을 쓴다 — 상류에서 이미 더 강하다. 내부 표기 불일치 한 건만 가져온다(⑧) |
| **노래 구간 자막(`singing.py`)** | v3hf 자신도 드라마에서는 **끄고 시작하는 계약**이다(BGM 오작동) |
| **`watch_trim` 빼기 전용 통째** | 티키타카 N 행은 TTS 실측 길이를 채워야 해서 '빼기'가 성립하지 않는다. 답은 교체이고, 그건 v3hf에 대응물이 없다 |
| **5걸음 좁혀가기 + 반려·재질의 체계** | 전제가 반대다(회차당 1편 vs 14버전 한 호출). 반려 = 14버전 전량 재생성이라 비용이 크고, 폭 우선 설계는 사용자 비용 결정이다 |
| **YuNet 프레이밍 전면 교체** | 티키타카가 Haar를 거부한 이유는 '**누가 주인공인가**'(옆얼굴·뒷모습·다중 얼굴)이고 그 정확도는 사용자 승인을 받았다. 측정이 필요한 것은 '**지금 어디가 가려지나**'라 역할이 다르다(⑪은 그 역할만 가져온다) |
| **Stage 4 줌·강조 자막·판정어 금지** | 줌·강조는 티키타카 레이아웃(납작한 밴드·유튜브 UI 안전 영역)과 별개 문제고, `LABEL_JUDGMENT_WORDS` 금지는 [극대노]·[팩트폭행] 리액션 문법과 정면으로 상충한다 — **채널 톤 결정 사안이지 기술 이식이 아니다** |
| **`pointer` 라벨(화면 글자 지시형)** | 화면 글자 기록(⑩)이 먼저 있어야 성립한다. 지금 지시형 문구는 근거가 없다 |
| **편 간 `plan` 반려 루프** | 티키타카에 'N편을 한 번에 기획하는 단계'가 없다 — 필요한 것은 생성 재시도가 아니라 **선정 측 벨트**다(⑤) |

---

### 부록 — 이식 시 반드시 함께 가져올 규율 3가지

1. **예산 상수 + 소진 시 동작을 같이 적는다.** 티키타카엔 예산 상수가 없고 호출이 컷·행 수에 비례한다 — ⑥·⑩·⑪에 상수가 없으면 편당 호출이 조용히 는다.
2. **프롬프트와 검증기는 한 벌로 고친다.** 검증기만 좁히면 모델은 매번 거절당하는 같은 산출을 낸다(v3hf·티키타카 양쪽의 반복 교훈).
3. **프롬프트 문구는 지문 밖, 스키마·규칙 버전은 지문 안.** 문구를 지문에 넣으면 오탈자 수정 한 번에 전량 재과금되고, 스키마를 빼면 새 필드가 영원히 빈 채 캐시가 재사용된다.
