# edit_overrides/v3 — 자막 원본 앵커(F-401) · 자막별 스타일(F-407) · 이미지 오버레이(F-408) · 회전(F-410)

정본. 오케스트레이터의 v3 스탬프 전환(0052)은 이 문서를 계약 기준으로 삼는다.
엔진 구현: `app/modules/edit_overrides.py`(검증·배치) · `app/modules/subtitle.py`(줄 스타일 렌더)
· `app/modules/renderer.py`(이미지 overlay 합성). 제목 오버라이드 실효화(F-409)도
편집실 계약의 일부라 이 문서 말미에 적는다.

## 왜 v3 인가

v2 까지 자막(subtitles)의 좌표는 **편집본 시간축**(쇼츠 0초 시작)뿐이었다. 구간(clips)을
고치면 그 좌표계 자체가 통째로 어긋나므로, 편집실은 구간과 자막을 **같이 보낼 수 없었다**
(구간만 먼저 → 새 자막을 보고 다시 편집하는 2-pass 강제). tts 는 처음부터
source_time_sec(원본 절대초)이 좌표이자 신원이라 이 문제가 없었다 — v3 는 같은 앵커를
자막에도 준다. 오케스트레이터 editor_assets 는 이미 자막마다 source_sec 을 화면에
내려보내고 있으므로(0042), 편집실은 받은 값을 그대로 되돌려 보내면 된다.

## 전체 스키마 예시

```json
{
  "schema": "edit_overrides/v3",
  "title":  { "top_title": "1줄\n2줄" },
  "clips": [
    { "start_sec": 742.5, "end_sec": 771.0, "role": "hook",
      "use_original_audio": true }
  ],
  "subtitles": [
    { "start_sec": 0.2, "end_sec": 2.3, "text": "앵커 있는 줄",
      "source_time_sec": 743.2,
      "style": { "size": 64, "y": 0.8, "color": "#FFDD00" } },
    { "start_sec": 2.4, "end_sec": 5.0, "text": "신규 줄 (앵커 없음)" }
  ],
  "tts": [
    { "source_time_sec": 743.0, "duration_sec": 3.5,
      "voice": "ko_female", "text": "내레이션" }
  ],
  "images": [
    { "file": "assets/arrow.png", "source_time_sec": 745.0, "duration_sec": 2.0,
      "x": 0.1, "y": 0.2, "w": 0.3, "layer": 1 }
  ]
}
```

v1·v2 의 규약(전량 교체 · pinned · 첫 variant 한정 · tts 좌표=신원)은 전부 그대로다.
v3 추가분만 아래에 적는다.

## subtitles[].source_time_sec — 원본 앵커 (F-401)

- **의미**: 이 줄이 붙어 있는 **원본 영상의 절대초**. 편집실 화면의 `source_sec`
  (editor_assets, 클립 밖이면 null)을 그대로 되돌려 보낸다.
- **배치 규칙** (`place_anchored_subtitles`, tts 의 `_resolve_cue_anchors` 와 같은 원리):
  1. 최종 클립 목록(silence_cut·클램프까지 끝난 확정 구간)에서 앵커를 **담은 클립**을
     찾는다. 정확 포함(`start ≤ t < end`)이 우선, 없으면 **슬롭 ±0.5s** 로 재판정한다
     (편집실 UI 와 동일 규약 — 경계 반올림 오차 관용). 슬롭 매칭은 클립 안쪽으로 클램프.
  2. 편집 시각 = 그 클립의 편집 오프셋 + (t − 클립 원본 start). 길이는 보낸
     `end_sec − start_sec` 그대로, 타임라인 끝에서 클램프.
  3. **고아**(어느 최종 클립에도 없음, 또는 변환 후 0.1s 미만): tts 고아와 같은 규칙 =
     **드롭**하고 렌더 로그에 남긴다
     (`[edit] 앵커 소재가 최종 타임라인에 없음 → 자막 드롭(tts 고아 규칙과 동일): …`).
     tts 의 중간 단계인 같은 (chunk,candidate) 조각 스냅은 자막에 그 메타데이터가 없어
     성립하지 않는다.
- **앵커 없는 항목**(신규 줄): 종전대로 `start_sec`(편집본 시간축)를 그대로 쓴다.
- **효과**: clips 와 subtitles 를 **같이 보내도 안전**하다. 재매핑(구간 변경 시 전사에서
  자막 재생성) 뒤에 오버라이드가 덮는 순서는 종전과 같고, 앵커 항목만 변환을 거친다.
- **캐시**: 배치 결과가 `subtitle_segments.json` 에 그대로 저장된다(편집본 시간축 정본).
  `source_time_sec` 은 변환 후 **제거**된다 — 편집실은 source_sec 을 스스로 역산한다.
  `style` 은 **남는다** — 오버라이드 없는 재렌더에서도 줄 스타일이 유지돼야 하기 때문.

## subtitles[].style — 줄 단위 스타일 (F-407)

채널/편 전역 프리셋(`subtitle_styles.py`) **위에** 그 줄만 얹는다. 키는 셋뿐이고,
모르는 키는 즉시 거절한다(조용한 무시 = 사람이 고친 값 증발).

| 키 | 의미 | 범위/형식 | ASS 구현 |
|----|------|-----------|----------|
| `size` | 폰트 크기 | 양수, 1080×1920 캔버스 px | 인라인 `{\fsN}` |
| `y` | 자막 **하단**이 놓일 세로 위치 | 0(상단)~1(하단), 캔버스 비율 | 이벤트 MarginV = (1−y)×1920 (최소 1 — MarginV=0 은 ASS 규약상 '스타일 기본값') |
| `color` | 글자색 | `"#RRGGBB"` | 인라인 `{\1c&HBBGGRR&}` |
| `rotate` | 줄 회전 (F-410) | -180~180, 도 단위, **시계방향 양수**(images 와 동일 규약), 기본 0 | 인라인 `{\frz}` — **ASS \frz 는 반시계 양수라 부호 반전은 엔진(subtitle.py)이 책임진다**. 편집실·오케스트레이터는 계약 부호만 보낸다. 회전 원점 = ASS 기본 \org = 그 줄의 정렬 앵커(하단 정렬 프리셋이면 자막 하단 중앙). 0 은 태그 자체를 안 박는다 |

- 하단 정렬 프리셋(현행 6종 전부 alignment=2)에서 MarginV 방식은 줄바꿈 폭·libass
  충돌 회피를 그대로 보존한다. 상단/중단 프리셋이 생기면 `\pos` 폴백이 동작한다.
- 명시한 키만 얹는다 — `{"color": "#FF0000"}` 이면 크기·위치는 프리셋 그대로.

## images — 이미지 오버레이 (F-408)

자막처럼 시간 구간을 갖는 이미지(스티커·짤)를 캔버스에 얹는다. ffmpeg `overlay` +
`enable=between` 으로 합성한다(`renderer._build_filtergraph`).

| 키 | 의미 | 비고 |
|----|------|------|
| `file` | 이미지 경로 | **run_dir 상대 경로**. 절대 경로·`..` 거절. **png/jpg/jpeg 만**(알파가 필요하면 png), 파일 상한 **10MB**(`IMAGE_MAX_BYTES`), 없는 파일·빈 파일은 파이프라인 시작 직후 즉시 실패(`resolve_image_files`) |
| `source_time_sec` | 표시 시작(원본 절대초) | ≥ 0. 자막 앵커와 같은 좌표계 |
| `duration_sec` | 표시 길이 | > 0. 타임라인 끝에서 클램프 |
| `x`, `y` | 좌상단 위치 | 0~1, 1080×1920 캔버스 대비 비율 → px 반올림 |
| `w` | 너비 | 0~1 비율 → px (높이는 원본 종횡비 유지 — `scale=W:-2`). **rotate 가 있어도 회전 전 원본 기준** — 회전으로 바운딩 박스가 커져도 w 해석은 안 바뀐다 |
| `layer` | 쌓임 순서 | 선택, 정수(기본 0). **≤ 0 = 자막 아래, ≥ 1 = 자막(ASS 두 겹) 위**. 같은 그룹 안에서는 오름차순으로 쌓이고 동률이면 배열 뒤가 위 |
| `rotate` | 회전 (F-410) | 선택, -180~180, 도 단위, **시계방향 양수**, 원점 = **이미지 중심**, 기본 0. ffmpeg `format=rgba` + `rotate`(ow/oh 재계산, fillcolor 투명)로 합성 — png 알파 보존, jpg 도 회전 모서리 여백은 투명. x/y(회전 전 좌상단)가 정의한 **중심이 고정**되도록 엔진이 overlay 좌표를 되물린다 |

- **모르는 키 즉시 거절 (F-410 부터 실제 강제)**: images 항목 허용 키는 위 표의
  8개(`IMAGE_KEYS`)뿐이다. F-410 이전의 v3 엔진(dc1060f 이하)은 images 항목에
  whitelist 가 없어 모르는 키를 **조용히 무시**했다 — 즉 rotate 를 실은 편집이
  rotate 이전 v3 엔진 노드에 가면 회전 없이 나간다(fail-loud 아님). 따라서
  **rotate 사용(0058·편집실 회전 UI)은 이 변경의 전 노드 배포가 선행 조건**이다.
  v2 이하 엔진은 어차피 스키마 단계에서 죽는다(아래 절).
- **역할 분담**: 엔진은 로컬 파일만 받는다 — 스토리지 다운로드는 오케스트레이터
  aivideo 어댑터가 key→run_dir 파일로 변환해 넘긴다(엔진이 스토리지 자격을 갖지
  않는 현행 규율). 그래서 파일 부재는 어댑터 버그이며, 조용히 빼는 대신 즉시 실패해
  검수함에 남긴다(제1원칙).
- **배치 규칙**(`place_anchored_images`): 자막 앵커(F-401)와 동일 — 담은 최종 클립의
  편집 오프셋 + 클립 내 상대시각, 포함 판정 슬롭 ±0.5s, 클립 밖 앵커·변환 후 0.1s
  미만은 tts 고아 규칙 = **드롭** + 렌더 로그. 구간 편집과 독립이라 clips 와 같이
  보내도 안전하다.
- 제목·작품명·플랫폼 표기는 이미지보다 먼저 그려진다 — 이미지가 그 위를 덮을 수 있다
  (layer 는 자막 대비 위치만 가른다).
- 첫 variant 한정, 전량 교체 — 다른 오버라이드와 같은 규약.

## 스키마 스탬프 규칙 (오케스트레이터 0052 가 지킬 것)

- subtitles 에 `source_time_sec`/`style` 이 하나라도 있거나 `images` 가 있으면 → **v3**
- 아니고 `tts` 가 있으면 → v2, 그 외 → v1 (종전 그대로)
- 엔진도 같은 규칙을 강제한다: **v3 전용 필드가 v1·v2 스탬프에 실려 오면 즉시 거절**
  (`… 은 edit_overrides/v3 전용입니다 — 스키마를 v3 로 찍으세요`). 스탬프와 내용이
  어긋난 채 받아주면 구 엔진 노드(조용히 무시)와 신 엔진 노드(반영)의 결과가 달라진다.

### 구 엔진의 v3 거절 — 실측 확인 (2026-08-19)

배포 전 안전장치의 근거. v2 엔진(84b2f0d, 이 변경 직전 HEAD)에 v3 문서를 넣으면:

```
EditOverrideError: 알 수 없는 스키마: 'edit_overrides/v3' (기대: edit_overrides/v1/edit_overrides/v2)
```

즉시 실패해 검수함에 남는다(fail-loud). 따라서 **v3 를 전 노드(6대)에 배포하기 전까지
오케스트레이터는 v3 를 찍으면 안 된다** — 찍는 순간 구 엔진 노드로 가는 편집이 전부
실패한다. 실패해도 조용히 잘못 나가는 것보다는 안전하지만, 배포 순서는
엔진 전 노드 → 0052 스탬프 전환이다.

## 제목 위치·크기 오버라이드 실효화 (F-409) — 편집실 제목 드래그의 엔진 파트

edit_overrides 스키마가 아니라 **`--design-*` 플래그 계약**이다(편집실 제목 드래그는
오케스트레이터가 채널 design 플래그로 내보낸다). 오케스트레이터 실측(2026-08-19)에서
둘 다 화면에 반영되지 않던 것을 고쳤다:

- **`--design-title-size N`**: 종전엔 `title_size`(줄바꿈 계산용)만 바꿔 실제 그리기
  (`title_sizes` [70,90] 기본)에 반영되지 않았다. 이제 cli 가 title_color→title_colors
  와 같은 패턴으로 `title_sizes` 를 조립한다. **N 은 1줄 기준이고, 줄 간 비율을 유지한
  채 전체를 스케일한다**(2줄 = N×90/70 반올림). 편집실 드래그 = 제목 블록 전체
  확대/축소라 두 줄의 위계(후킹 줄이 더 크다)를 유지하는 쪽을 택했다 — 동일 크기를
  원하면 후속에서 `--design-title-size2` 를 추가하는 것이 자연스럽다.
- **`--design-title-y-fixed`** (불리언, 기본 false) 신설: 종전엔 동적 배치(영상 위
  20px)가 항상 이기고 `title_y` 는 여백 부족 폴백으로만 쓰였다. 참이면 동적 배치 대신
  `title_y` 를 그대로 쓴다(`DesignConfig.title_y_fixed`). 기본 false 라 기존 채널 전부
  무영향. 편집실 제목 드래그(오케스트레이터 후속)가 `design.title_y_fixed` 로 나간다 —
  **오케스트레이터 어댑터 `CHANNEL_DESIGN_FLAGS` 에 `title_y_fixed` 키 추가 필요**.

## 엔진 실측 (2026-08-19, 합성 run·resume)

180s 합성 소스로 v2 시절 checkpoint 를 구성하고 `--from-step render` +
v3 오버라이드(구간 변경 100~120→95~120 + 앵커 자막 + 줄 스타일 + 고아 자막)로 재렌더:

- 원본 105초 앵커 자막 → 편집 25.0s (= hook 15s + (105−95)) 에 배치.
  편집실이 보낸 낡은 편집좌표(20.0s)가 아니라 **장면을 따라왔다**.
- ASS: `Dialogue: 0,0:00:25.00,0:00:27.50,Default,,,,384,, {\fs64\1c&H00DDFF&}앵커 자막 실측`
  — size 64 · #FFDD00(BGR 00DDFF) · y=0.8(MarginV 384) 전부 반영, 프레임 캡처로 확인.
- 고아(원본 60초, 최종 구간 밖) → 드롭 + 로그, 무앵커 신규 줄 → 편집좌표 그대로.
- `subtitle_segments.json`: 배치 결과 + style 저장, source_time_sec 제거 확인.

### images 렌더 실측 (F-408, 2026-08-19 같은 방식)

180s 합성 소스, pinned 구간 hook[10,25)+payoff[100,120) → 35s 타임라인, 이미지 2개
(png 알파 스티커 layer 0 · jpg 배너 layer 1, 둘 다 자막과 같은 시간 창):

- 앵커 변환: 원본 105.5s → 편집 20.5s (= 15 + 5.5), 원본 12s → 편집 2.0s — 계산과 일치.
- 위치·크기: w=0.3 → 324px(세로 원본비 유지), (0.1, 0.35) → (108, 672)px — 프레임 캡처
  픽셀 확인. png 반투명(알파 200) 배경 비침 확인.
- 레이어: 자막과 공간 겹침 프레임에서 **자막 글줄이 layer 0 스티커 위에**, **layer 1
  배너가 자막 위에** 그려짐 — ≤0/≥1 경계 픽셀 확인.
- 렌더 소요: 편집 재렌더 재개 **1.1초** (이미지 0개일 때와 동일 자릿수 — 멈춤 기준
  30초 대비 여유. overlay 2개는 enable 창 밖에서 비용이 사실상 없다).

### rotate 실측 (F-410, 2026-08-19 같은 run 재사용)

같은 35s 합성 run 에 rotate 를 얹어 재렌더: png 스티커(400×300, 알파 200) rotate 45
layer 0 · jpg 배너(600×200) rotate 90 layer 1 — 둘 다 자막과 같은 시간 창(편집
20.5~23.5s), 자막 1줄 style.rotate −8.

- **방향 규약**: ffmpeg `rotate` 양수 = **시계방향** 을 비대칭 표준 이미지(+30°)로
  단독 실측 — 계약(시계방향 양수)과 부호 변환 없이 일치한다. 자막만 ASS `\frz` 가
  반시계 양수라 subtitle.py 가 부호를 반전한다(−8 → `{\frz8}`, 우측 끝이 올라간
  기울기 프레임 확인).
- **중심 고정·좌표 일치**: 스티커 w=0.5 → 540px, 스케일 540×404, 45° 바운딩 박스
  668×668, overlay (216,922) → (152,790) — 회전 전 중심 (486,1124) 그대로. 배너
  486px → 486×162, 90° 박스 162×486, overlay (486,1056) → (648,894). 로그·수계산·
  프레임 픽셀 전부 일치.
- **알파**: png 반투명이 회전 후에도 배경 비침(픽셀 (237,91,44) = 빨강×배경 블렌드),
  회전 바운딩 박스의 빈 모서리는 투명(배경 그대로) — jpg 도 `format=rgba` 선행으로
  모서리가 투명이다.
- **레이어**: 자막 글리프가 45° 스티커(layer 0) 위에, 90° 배너(layer 1)가 자막 위에
  — 회전이 레이어 규약을 안 바꾼다.
- **정규화 경로 회귀 1건**: `overrides_subtitles` 의 style 정규화 whitelist 가
  rotate 를 조용히 떨어뜨리는 것을 실측에서 발견·수정(회귀 테스트 추가). 캐시
  `subtitle_segments.json` 에 rotate 가 저장되는 것 확인.
- **렌더 소요: 1.1~1.2초** — F-408(회전 없음)과 동일 자릿수, 멈춤 기준 30초 대비
  여유. 회전 2개 + scale 명시 경로의 추가 비용은 측정 오차 안이다.
