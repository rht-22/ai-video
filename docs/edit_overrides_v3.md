# edit_overrides/v3 — 자막 원본 앵커(F-401) · 자막별 스타일(F-407) · images 스키마

정본. 오케스트레이터의 v3 스탬프 전환(0052)은 이 문서를 계약 기준으로 삼는다.
엔진 구현: `app/modules/edit_overrides.py`(검증·배치) · `app/modules/subtitle.py`(줄 스타일 렌더).

## 왜 v3 인가

v2 까지 자막(subtitles)의 좌표는 **편집본 시간축**(쇼츠 0초 시작)뿐이었다. 구간(clips)을
고치면 그 좌표계 자체가 통째로 어긋나므로, 편집실은 구간과 자막을 **같이 보낼 수 없었다**
(구간만 먼저 → 새 자막을 보고 다시 편집하는 2-pass 강제). tts 는 처음부터
source_time_sec(원본 절대초)이 좌표이자 신원이라 이 문제가 없었다 — v3 는 같은 앵커를
자막에도 준다. 오케스트레이터 editor_assets 는 이미 자막마다 source_sec 을 화면에
내려보내고 있으므로(0042), 편집실은 받은 값을 그대로 되돌려 보내면 된다.

## 전체 스키마 예시

```json
{
  "schema": "edit_overrides/v3",
  "title":  { "top_title": "1줄\n2줄" },
  "clips": [
    { "start_sec": 742.5, "end_sec": 771.0, "role": "hook",
      "use_original_audio": true }
  ],
  "subtitles": [
    { "start_sec": 0.2, "end_sec": 2.3, "text": "앵커 있는 줄",
      "source_time_sec": 743.2,
      "style": { "size": 64, "y": 0.8, "color": "#FFDD00" } },
    { "start_sec": 2.4, "end_sec": 5.0, "text": "신규 줄 (앵커 없음)" }
  ],
  "tts": [
    { "source_time_sec": 743.0, "duration_sec": 3.5,
      "voice": "ko_female", "text": "내레이션" }
  ],
  "images": [
    { "file": "assets/arrow.png", "source_time_sec": 745.0, "duration_sec": 2.0,
      "x": 0.1, "y": 0.2, "w": 0.3, "layer": 1 }
  ]
}
```

v1·v2 의 규약(전량 교체 · pinned · 첫 variant 한정 · tts 좌표=신원)은 전부 그대로다.
v3 추가분만 아래에 적는다.

## subtitles[].source_time_sec — 원본 앵커 (F-401)

- **의미**: 이 줄이 붙어 있는 **원본 영상의 절대초**. 편집실 화면의 `source_sec`
  (editor_assets, 클립 밖이면 null)을 그대로 되돌려 보낸다.
- **배치 규칙** (`place_anchored_subtitles`, tts 의 `_resolve_cue_anchors` 와 같은 원리):
  1. 최종 클립 목록(silence_cut·클램프까지 끝난 확정 구간)에서 앵커를 **담은 클립**을
     찾는다. 정확 포함(`start ≤ t < end`)이 우선, 없으면 **슬롭 ±0.5s** 로 재판정한다
     (편집실 UI 와 동일 규약 — 경계 반올림 오차 관용). 슬롭 매칭은 클립 안쪽으로 클램프.
  2. 편집 시각 = 그 클립의 편집 오프셋 + (t − 클립 원본 start). 길이는 보낸
     `end_sec − start_sec` 그대로, 타임라인 끝에서 클램프.
  3. **고아**(어느 최종 클립에도 없음, 또는 변환 후 0.1s 미만): tts 고아와 같은 규칙 =
     **드롭**하고 렌더 로그에 남긴다
     (`[edit] 앵커 소재가 최종 타임라인에 없음 → 자막 드롭(tts 고아 규칙과 동일): …`).
     tts 의 중간 단계인 같은 (chunk,candidate) 조각 스냅은 자막에 그 메타데이터가 없어
     성립하지 않는다.
- **앵커 없는 항목**(신규 줄): 종전대로 `start_sec`(편집본 시간축)를 그대로 쓴다.
- **효과**: clips 와 subtitles 를 **같이 보내도 안전**하다. 재매핑(구간 변경 시 전사에서
  자막 재생성) 뒤에 오버라이드가 덮는 순서는 종전과 같고, 앵커 항목만 변환을 거친다.
- **캐시**: 배치 결과가 `subtitle_segments.json` 에 그대로 저장된다(편집본 시간축 정본).
  `source_time_sec` 은 변환 후 **제거**된다 — 편집실은 source_sec 을 스스로 역산한다.
  `style` 은 **남는다** — 오버라이드 없는 재렌더에서도 줄 스타일이 유지돼야 하기 때문.

## subtitles[].style — 줄 단위 스타일 (F-407)

채널/편 전역 프리셋(`subtitle_styles.py`) **위에** 그 줄만 얹는다. 키는 셋뿐이고,
모르는 키는 즉시 거절한다(조용한 무시 = 사람이 고친 값 증발).

| 키 | 의미 | 범위/형식 | ASS 구현 |
|----|------|-----------|----------|
| `size` | 폰트 크기 | 양수, 1080×1920 캔버스 px | 인라인 `{\fsN}` |
| `y` | 자막 **하단**이 놓일 세로 위치 | 0(상단)~1(하단), 캔버스 비율 | 이벤트 MarginV = (1−y)×1920 (최소 1 — MarginV=0 은 ASS 규약상 '스타일 기본값') |
| `color` | 글자색 | `"#RRGGBB"` | 인라인 `{\1c&HBBGGRR&}` |

- 하단 정렬 프리셋(현행 6종 전부 alignment=2)에서 MarginV 방식은 줄바꿈 폭·libass
  충돌 회피를 그대로 보존한다. 상단/중단 프리셋이 생기면 `\pos` 폴백이 동작한다.
- 명시한 키만 얹는다 — `{"color": "#FF0000"}` 이면 크기·위치는 프리셋 그대로.

## images — 스키마 선언만 (렌더는 후속 세션)

| 키 | 의미 | 비고 |
|----|------|------|
| `file` | 이미지 경로 | **run_dir 상대 경로**. 절대 경로·`..` 거절 |
| `source_time_sec` | 표시 시작(원본 절대초) | ≥ 0. 자막 앵커와 같은 좌표계 |
| `duration_sec` | 표시 길이 | > 0 |
| `x`, `y` | 좌상단 위치 | 0~1, 1080×1920 캔버스 대비 비율 |
| `w` | 너비 | 0~1 비율 (높이는 원본 종횡비 유지) |
| `layer` | 쌓임 순서 | 선택, 정수 |

**2026-08-19 현재 렌더 미구현**: 검증(`validate_overrides`)은 위 스키마를 받지만,
렌더 진입 게이트(`ensure_renderable`, pipeline 재개 직후)가 **fail-loud 로 거절**한다 —
`edit_overrides/v3 images 는 아직 렌더 미구현입니다`. 조용히 빼고 렌더하면 사람이 올린
이미지가 소리 없이 사라진 영상이 나가기 때문(제1원칙). 이미지 오버레이 렌더가 구현되면
이 게이트를 지우는 것이 곧 기능 활성화다.

## 스키마 스탬프 규칙 (오케스트레이터 0052 가 지킬 것)

- subtitles 에 `source_time_sec`/`style` 이 하나라도 있거나 `images` 가 있으면 → **v3**
- 아니고 `tts` 가 있으면 → v2, 그 외 → v1 (종전 그대로)
- 엔진도 같은 규칙을 강제한다: **v3 전용 필드가 v1·v2 스탬프에 실려 오면 즉시 거절**
  (`… 은 edit_overrides/v3 전용입니다 — 스키마를 v3 로 찍으세요`). 스탬프와 내용이
  어긋난 채 받아주면 구 엔진 노드(조용히 무시)와 신 엔진 노드(반영)의 결과가 달라진다.

### 구 엔진의 v3 거절 — 실측 확인 (2026-08-19)

배포 전 안전장치의 근거. v2 엔진(84b2f0d, 이 변경 직전 HEAD)에 v3 문서를 넣으면:

```
EditOverrideError: 알 수 없는 스키마: 'edit_overrides/v3' (기대: edit_overrides/v1/edit_overrides/v2)
```

즉시 실패해 검수함에 남는다(fail-loud). 따라서 **v3 를 전 노드(6대)에 배포하기 전까지
오케스트레이터는 v3 를 찍으면 안 된다** — 찍는 순간 구 엔진 노드로 가는 편집이 전부
실패한다. 실패해도 조용히 잘못 나가는 것보다는 안전하지만, 배포 순서는
엔진 전 노드 → 0052 스탬프 전환이다.

## 엔진 실측 (2026-08-19, 합성 run·resume)

180s 합성 소스로 v2 시절 checkpoint 를 구성하고 `--from-step render` +
v3 오버라이드(구간 변경 100~120→95~120 + 앵커 자막 + 줄 스타일 + 고아 자막)로 재렌더:

- 원본 105초 앵커 자막 → 편집 25.0s (= hook 15s + (105−95)) 에 배치.
  편집실이 보낸 낡은 편집좌표(20.0s)가 아니라 **장면을 따라왔다**.
- ASS: `Dialogue: 0,0:00:25.00,0:00:27.50,Default,,,,384,, {\fs64\1c&H00DDFF&}앵커 자막 실측`
  — size 64 · #FFDD00(BGR 00DDFF) · y=0.8(MarginV 384) 전부 반영, 프레임 캡처로 확인.
- 고아(원본 60초, 최종 구간 밖) → 드롭 + 로그, 무앵커 신규 줄 → 편집좌표 그대로.
- `subtitle_segments.json`: 배치 결과 + style 저장, source_time_sec 제거 확인.
