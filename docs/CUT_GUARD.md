# 덮개 컷 경계 검사 (시험 옵션)

`python -m app.tikitaka … --cover-cut-guard`로 켠다. 기본 실행은 바뀌지 않는다.
저장된 테이블 재개에도 적용하며 원본 테이블은 덮어쓰지 않는다.

- 기존 `scene_cuts`와 선택 구간의 앞뒤 0.45초를 원본 fps로 확인한다.
  낮은 대비 때문에 기존 목록이 놓친 경계도 선택 구간 주변에서는 찾는다.
- 연속된 원본 구간을 먼저 합쳐 기술적 2초 분할을 카메라 컷으로 세지 않는다.
- 실제 샷이 출력에서 0.30초 미만 남으면 검토 후보로 기록한다. 이 수치는
  보편적인 편집 규칙이 아니라 시험 기준이다. 손·소품의 큰 움직임도 후보가 될 수 있다.
- N 구간의 잘린 샷 머리·꼬리만 자동 수정한다. 승인된 span 안의 동일 샷 여유와
  기존 배속의 여유(1.0~1.2)를 사용하고 각 행의 출력 프레임 수를 보존한다.
  내레이션 문구·음성 파일·시작·종료와 S/A 구간은 변경하지 않는다.
- 내레이션 길이를 지킬 화면이 부족하거나 핵심 근거 span이 사라지면 해당 행의
  수정은 전부 취소하고 렌더를 막는다. 정지·슬로우·새 span 선택은 없다.
- 원본 자체의 짧은 샷과 S/A 후보는 기록만 한다. `needs_review`는 자동 수정 성공을
  뜻하지 않는다. 화면 반복·동작 되감기 등 의미 판단은 이 버전의 범위 밖이다.

`cut_guard_vN.json`은 수정·미해결·전체 편집표 후보 기록,
`grid_table_guarded_vN.json`은 실제 렌더에 전달할 수정 테이블이다.
원본 프레임 검사는 `cut_guard_probes/`에 소스 식별자와 설정을 포함해 캐시한다.
검사는 조립 뒤, watch-trim·스타일·렌더 앞에서 실행된다. **최종 렌더의 모든
프레임을 검사하는 기능은 아니다.** 실제 렌더 전후 비교로 별도 확인해야 한다.

## 기존 결과로 비용 없는 대조

```sh
python -m scripts.check_cover_cuts \
  --job-dir outputs_tikitaka_grid/가왕쇼_10_20260917 \
  --versions 2 4 --out tmp/cut-guard-ab
```

LLM·TTS 호출 없이 별도 폴더에 테이블과 보고서를 만든다. 원본 영상·음성은 그대로다.
추가 제한 구간이 있으면 `--blocked-json`에 `[시작초, 종료초]` 쌍 목록 파일을 전달한다.
자동 로드하는 분석 제외·암전 구간 외의 채널/가이드 제한은 이 파일에 포함해야 한다.
정식 CLI에서는 현재 실행의 제외·암전 설정을 그대로 전달한다.

검증: `python -m pytest -q tests/test_tikitaka_cut_guard.py`
