# 2026-08-18 실측: YouTube 소스 5개 채널이 한 시간 사이에 전부
# `unable to download video data: HTTP Error 403` 으로 죽었다(재시도해도 동일) — 메타데이터
# 조회는 통과하고 스트림 단계에서만 막히는, 추출기가 낡았을 때의 전형적인 모양이다.
# 🛑 하한(>=)이 아니라 **정확한 핀(==)** 이다. 2026-08-18 하루가 통째로 그 이유다.
# 그날 유튜브가 android_vr 을 막았고(상류 주석: "Since 2026.08.17, ALL formats
# (including live HLS and itag 18) are 403'd with version 1.65.10"), 2026.7.4 의 기본
# 클라이언트가 거기 걸려 YouTube 소스 5개 채널이 전멸했다. 증상은 1080p(137, 184.85MiB)를
# 받다가 **항상 5.3% 부근에서 403** — 쿠키·조각 크기(1M/10M/1G)·dashy·PO 토큰(bgutil)·
# curl_cffi 위장 무엇으로도 안 뚫렸다.
# 08-18 나이틀리가 기본에서 android_vr 을 빼고 visionos 를 1순위로 올리자 같은 영상이
# 그대로 완주했다(mm-05 실측: 184.85MiB 전량, default 10초 / visionos 7초).
#
# 이 싸움은 며칠 단위로 뒤집힌다. '>=' 로 두면 안 되는 이유가 둘이다.
#   · pip install -r 은 조건을 이미 만족하면 업그레이드하지 않는다(updater._pip_sync).
#     하한만 올리면 6대가 서로 다른 나이틀리를 쓰게 되고 "어떤 맥에서만 죽는다"가 된다.
#   · 반대로 검증 안 된 최신 나이틀리가 조용히 들어오는 것도 위험하다.
# **실측으로 통과를 확인한 빌드만 핀으로 올린다.** 유튜브가 또 막으면 여기부터 본다.
#
